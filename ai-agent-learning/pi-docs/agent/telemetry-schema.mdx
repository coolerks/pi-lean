# Pi Agent 遥测 Schema

> 本页根据 `packages/agent/docs/telemetry-schema.md` 重新翻译，研究基线为 commit `853a80d26c90a14c1886f0ebb8ffaae133ca2185`。字段名、类型名、枚举值和 schema 标识符保持原样。

## 中文译文

这份文档定义的是遥测契约，不是日志字段的随意清单。它说明每类 Span 表示什么、应该挂在哪个父 Span 下、默认状态是什么、什么情况算错误，以及开始和结束时可以记录哪些属性。Schema 版本为 `1`。下列表格保留契约中的英文列名，便于与源 Schema 和实现代码逐项核对。

> 译者注：Span 是带有开始和结束边界的一段操作；属性用于描述这段操作，父子关系用于还原调用树。它们负责观察，不会替代 Session 的持久化记录，也不能单独证明某个外部工具副作用已经完成。

## AI 请求 Schema

### `pi.ai.request`

`pi.ai.request` 表示向 AI provider 发起的一次逻辑请求。它可能对应流式请求、延后结果的获取或取消、以及图像生成，并不等同于某一个 HTTP 数据包。

- **父 Span：** `root` 或任意调用方 Span。
- **默认状态：** `ok`。
- **错误条件：** 操作抛出异常，或返回错误结果。

#### 开始属性（Start attributes）

以下属性在请求开始时记录：

| Name | Type | Required | Values | Notes | Description（中文） |
| --- | --- | --- | --- | --- | --- |
| `pi.ai.operation` | `string` | yes | `stream`、`fetch_deferred`、`cancel_deferred`、`generate_images` |  | 逻辑上的 provider 操作。 |
| `pi.ai.provider` | `string` | yes |  |  | 选中的 provider id。 |
| `pi.ai.model` | `string` | yes |  |  | 请求使用的 model id。 |
| `pi.ai.api` | `string` | yes |  |  | 使用的 provider API id。 |
| `pi.ai.streaming` | `boolean` | yes |  |  | 该操作是否返回流。 |
| `pi.ai.deferred` | `boolean` | no |  |  | 该操作是否请求或参与延后执行。 |

所有结束属性都是可选的完成补充信息：

#### 事件（Events）

源 Schema 没有为 `pi.ai.request` 声明专用 Span 事件（`No declared span events`）。这不表示系统没有流事件，而是流事件属于其他事件契约。

## 阅读这些字段时的几个边界

### 接受、完成与失败不是同一件事

`pi.harness.run` 的开始属性描述一次已经被接受的调用；结束属性才说明它最终是 `completed`、`aborted`、`failed` 还是 `suspended`。不能因为看到了开始 Span，就把运行记作成功。

### 属性基数与隐私

`high cardinality` 表示值的种类很多，例如每个会话或操作一个 id；`low cardinality` 表示值的种类有限，适合做聚合。高基数 id 对定位单次故障很有用，但不应直接成为指标标签，否则会造成时间序列数量失控。

源 Schema 没有要求把 prompt、completion、工具参数、工具输出、文件内容、payload、headers 或 credentials 写入属性。默认 exporter 应采用数据最小化原则，只记录诊断所需的身份、耗时、状态、usage 和低基数错误。Authorization、cookie 和 API key 不应进入普通遥测。

> 译者注：`pi.tool.replay=safe` 是声明的重放策略，不是幂等性的证明；`pi.session.write` 说明会话变更已提交，也不能证明外部操作已经完成。遇到故障时仍需要独立的操作记录和恢复逻辑。

### Java 与 Go 对照

| Pi/TypeScript | Java | Go | 说明 |
| --- | --- | --- | --- |
| Span 上下文与回调 | OpenTelemetry `Context`、try-with-resources scope、Listener | `context.Context`、显式 recorder | 父关系应显式传递，不依赖隐式全局状态。 |
| `AbortSignal` | `CancellationToken`、线程中断 | `ctx.Done()` | 取消表示意图，未必撤销远端计费。 |
| 高基数属性 | 不可变 map 加脱敏 | struct/map，默认禁止 payload | 记录 id 前考虑采样、权限和查询成本。 |
| 父 Span | `Span.makeCurrent()` 或显式 parent | context 中携带 trace state | Span 生命周期必须成对结束。 |
| no-op telemetry | no-op interface | no-op function/recorder | 遥测失败不应改变 Agent 主流程。 |

Java 的 Listener 适合测试进程内事件；OpenTelemetry exporter 还涉及批处理、采样和网络失败。Go 可以用 struct 保存稳定属性，以 `context.Context` 传递取消和 trace metadata；不要把 context 当成可变业务状态仓库。

## 实验

1. 用 `ScriptedModel` 发起只返回文本的请求，分别记录 `pi.ai.request`、`pi.harness.run` 和 `pi.session.write` 的 parent、开始属性与结束结果。
2. 让 fake model 第一次返回 429、第二次返回文本，观察重试产生的请求和 `pi.harness.step` 的 `pi.step.attempt`。
3. 让一个 before hook 阻止工具，再让工具执行抛错，比较 hook outcome、`pi.tool.is_error` 和运行结果。
4. 在 prompt、工具参数和文件内容中放入假 token，检查 exporter 是否将其脱敏；不要使用真实凭据。

## 小结

这份 Schema 划分了不同观察边界：`pi.ai.request` 描述 provider 操作，`pi.harness.run`、`pi.harness.compaction` 和 `pi.harness.navigation` 描述已接受的调用，checkpoint、turn、step 描述运行结构，tool、hook、sleep 和 event_handler 描述执行或监听，`pi.session.write` 描述会话变更已经提交。

阅读一条遥测记录时，依次检查 Span 名称、父关系、开始时的身份、结束时的结果、usage/error 以及隐私策略。遥测是被动诊断信息，不是 Agent Loop、Session reducer 或持久化恢复机制的替代品。
