# 会话：保存、恢复与分支

> 本页根据 `packages/coding-agent/docs/sessions.md` 重新翻译，研究基线为 `853a80d26c90a14c1886f0ebb8ffaae133ca2185`。命令、配置字段、API 名称和路径保留原样。

## 中文导读

Pi 把对话保存为会话（Session），这样你可以继续之前的工作、从旧的对话轮次创建分支，也可以重新查看过去走过的路径。本页介绍会话文件、交互命令、恢复和删除操作，然后解释 `/tree`、`/fork`、`/clone` 的区别以及分支摘要。

> 译者注：Session 是持久化的会话记录；Context 是某一次模型请求实际使用的上下文；Memory 则是更宽泛的长期信息概念。`/tree` 改变会话树中的当前位置，`/compact` 改变后续请求使用的上下文，二者不是同一个操作。

## 中文译文

## 会话存储

会话会自动保存到 `~/.pi/agent/sessions/`，并按工作目录组织。每个会话是一个具有树结构的 JSONL 文件。

```bash
pi -c                  # Continue most recent session
pi -r                  # Browse and select from past sessions
pi --no-session        # Ephemeral mode; do not save
pi --name "my task"    # Set session display name at startup
pi --session <path|id> # Use a specific session file or partial session ID
pi --fork <path|id>    # Fork a session file or partial session ID into a new session
```

在交互模式中使用 `/session`，可以查看当前会话文件、会话 ID、消息数量、token 数和费用。

关于 JSONL 文件格式和 `SessionManager` API，请参阅 [Session Format](/pi-docs/coding-agent/session-format)。

> 译者注：命令示例中的 `<path|id>` 是命令行参数占位符，不是要原样输入的文件名。会话按工作目录分组，因此在错误的项目目录中执行 `pi -r`，可能会误以为历史会话丢失。

## 会话命令

| 命令 | 说明 |
| --- | --- |
| `/resume` | 浏览并选择以前的会话 |
| `/new` | 开始新会话 |
| `/name <name>` | 设置当前会话的显示名称 |
| `/session` | 显示会话信息 |
| `/tree` | 浏览当前会话树 |
| `/fork` | 从以前的用户消息创建新会话 |
| `/clone` | 把当前活动分支复制到新会话 |
| `/compact [prompt]` | 总结较早的上下文；详见 [Compaction](/pi-docs/coding-agent/compaction) |
| `/export [file]` | 将会话导出为 HTML |
| `/share` | 上传为私有 GitHub gist，并获得可分享的 HTML 链接 |

## 恢复和删除会话

`/resume` 会打开当前项目的交互式会话选择器；启动时使用 `pi -r` 会打开同一个选择器。

在选择器中，你可以：

- 直接输入文字进行搜索；
- 使用 `Ctrl+P` 显示或隐藏路径；
- 使用 `Ctrl+S` 切换排序方式；
- 使用 `Ctrl+N` 只显示已命名的会话；
- 使用 `Ctrl+R` 重命名会话；
- 使用 `Ctrl+D` 删除会话，然后确认操作。

如果系统中存在 `trash` 命令，Pi 会优先使用它删除会话，而不是永久移除文件。

> 译者注：恢复只会恢复会话记录和可重建的上下文，不会自动撤销或确认外部工具已经产生的副作用。比如上一次运行已经修改了数据库，但进程在保存会话前退出，重新打开会话并不能据此判断数据库状态。

## 命名会话

使用 `/name <name>` 设置易读的会话名称：

```text
/name Refactor auth module
```

也可以在启动时使用 `--name` 或 `-n`：

```bash
pi --name "Refactor auth module"
pi --name "CI audit" -p "Review this build failure"
```

命名后的会话更容易在 `/resume` 和 `pi -r` 中找到。

## 使用 `/tree` 创建分支

会话以树的形式保存。每个条目都有 `id` 和 `parentId`，当前所在位置称为活动叶子（active leaf）。`/tree` 允许你跳到历史中的任意位置，并从那里继续，而不必创建新的会话文件。

<p align="center"><img src="https://github.com/coolerks/pi-lean/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/docs/images/tree-view.png?raw=1" alt="会话树视图" width="600" /></p>

树的大致形状如下：

```text
├─ user: "Hello, can you help..."
│  └─ assistant: "Of course! I can..."
│     ├─ user: "Let's try approach A..."
│     │  └─ assistant: "For approach A..."
│     │     └─ user: "That worked..."  ← active
│     └─ user: "Actually, approach B..."
│        └─ assistant: "For approach B..."
```

### 树控制

| 按键 | 操作 |
| --- | --- |
| ↑/↓ | 浏览当前可见的条目 |
| ←/→ | 上一页或下一页 |
| Ctrl+←/Ctrl+→ 或 Alt+←/Alt+→ | 折叠、展开，或在分支片段之间跳转 |
| Shift+L | 为选中条目设置或清除标签 |
| Shift+T | 切换标签的时间戳显示 |
| Enter | 选择条目 |
| Escape/Ctrl+C | 取消 |
| Ctrl+O | 循环切换过滤模式 |

过滤模式包括 `default`、`no-tools`、`user-only`、`labeled-only` 和 `all`。使用 [Settings](/pi-docs/coding-agent/settings) 中的 `treeFilterMode` 配置默认过滤模式。

### 选择行为

选择 user 或 custom message 时：

1. 把 leaf 移到所选消息的父条目。
2. 把所选消息的文本放入编辑器。
3. 你可以修改文本并重新提交，从而创建一个新分支。

选择 assistant、tool、compaction 或其他非用户条目时：

1. 把 leaf 移到所选条目。
2. 清空编辑器。
3. 你可以从该位置继续对话。

选择根 user message 时，会把 leaf 重置为空会话，并把原始提示词放回编辑器。

> 译者注：选择 user message 的特殊行为是为了让“修改问题后重试”自然地形成新分支；选择 assistant 或 tool 条目则表示从已有执行结果继续，不会自动把文本重新放进编辑器。

## `/tree`、`/fork` 和 `/clone`

| 特性 | `/tree` | `/fork` | `/clone` |
| --- | --- | --- | --- |
| 输出 | 同一个会话文件 | 新会话文件 | 新会话文件 |
| 浏览范围 | 完整会话树 | 用户消息选择器 | 当前活动分支 |
| 常见用途 | 在原会话中探索多个方案 | 从较早提示开始独立任务 | 复制当前工作后再继续 |
| 摘要 | 可选分支摘要 | 无 | 无 |

如果希望把多个方案放在同一棵树中，使用 `/tree`。如果需要独立的会话文件，使用 `/fork` 或 `/clone`。

> 译者注：`/fork` 和 `/clone` 都会创建文件副本，但起点不同：前者从过去的用户消息开始，后者复制当前活动分支。它们都不会把旧文件的其他 sibling 分支混入新会话。

## 分支摘要

当 `/tree` 从一个分支切换到另一个分支时，Pi 可以总结被放弃的分支，并把摘要挂到新的位置。这样可以保留离开路径中的重要背景，而不必把整条分支重新播放一遍。

出现提示时，可以选择：

1. 不生成摘要；
2. 使用默认提示词生成摘要；
3. 提供自定义重点来生成摘要。

分支摘要的内部实现和 Extension hook 见 [Compaction](/pi-docs/coding-agent/compaction)。

> 译者注：分支摘要是导航信息，不是被放弃分支的逐字副本。如果某个决定、文件修改或外部操作不可丢失，应把它保存在适合恢复的记录中，不能只依赖自然语言摘要。

## 会话格式

会话文件使用 JSONL，包含消息条目、模型变更、思考级别变更、标签、上下文压缩、分支摘要和扩展条目。

解析器、Extension、SDK 用法以及完整的 `SessionManager` API，请参阅 [Session Format](/pi-docs/coding-agent/session-format)。

# Sessions

Pi saves conversations as sessions so you can continue work, branch from earlier turns, and revisit previous paths.

## Session Storage

Sessions auto-save to `~/.pi/agent/sessions/`, organized by working directory. Each session is a JSONL file with a tree structure.

```bash
pi -c                  # Continue most recent session
pi -r                  # Browse and select from past sessions
pi --no-session        # Ephemeral mode; do not save
pi --name "my task"    # Set session display name at startup
pi --session <path|id> # Use a specific session file or partial session ID
pi --fork <path|id>    # Fork a session file or partial session ID into a new session
```

Use `/session` in interactive mode to see the current session file, session ID, message count, tokens, and cost.

For the JSONL file format and SessionManager API, see [Session Format](session-format.md).

## Session Commands

| Command | Description |
|---------|-------------|
| `/resume` | Browse and select previous sessions |
| `/new` | Start a new session |
| `/name <name>` | Set the current session display name |
| `/session` | Show session info |
| `/tree` | Navigate the current session tree |
| `/fork` | Create a new session from a previous user message |
| `/clone` | Duplicate the current active branch into a new session |
| `/compact [prompt]` | Summarize older context; see [Compaction](compaction.md) |
| `/export [file]` | Export session to HTML |
| `/share` | Upload as private GitHub gist with shareable HTML link |

## Resuming and Deleting Sessions

`/resume` opens an interactive session picker for the current project. `pi -r` opens the same picker at startup.

In the picker you can:

- search by typing
- toggle path display with Ctrl+P
- toggle sort mode with Ctrl+S
- filter to named sessions with Ctrl+N
- rename with Ctrl+R
- delete with Ctrl+D, then confirm

When available, pi uses the `trash` CLI for deletion instead of permanently removing files.

## Naming Sessions

Use `/name <name>` to set a human-readable session name:

```text
/name Refactor auth module
```

Set the name at startup with `--name` or `-n`:

```bash
pi --name "Refactor auth module"
pi --name "CI audit" -p "Review this build failure"
```

Named sessions are easier to find in `/resume` and `pi -r`.

## Branching with `/tree`

Sessions are stored as trees. Every entry has an `id` and `parentId`, and the current position is the active leaf. `/tree` lets you jump to any previous point and continue from there without creating a new file.

<p align="center"><img src="images/tree-view.png" alt="Tree View" width="600"></p>

Example shape:

```text
├─ user: "Hello, can you help..."
│  └─ assistant: "Of course! I can..."
│     ├─ user: "Let's try approach A..."
│     │  └─ assistant: "For approach A..."
│     │     └─ user: "That worked..."  ← active
│     └─ user: "Actually, approach B..."
│        └─ assistant: "For approach B..."
```

### Tree Controls

| Key | Action |
|-----|--------|
| ↑/↓ | Navigate visible entries |
| ←/→ | Page up/down |
| Ctrl+←/Ctrl+→ or Alt+←/Alt+→ | Fold/unfold or jump between branch segments |
| Shift+L | Set or clear a label on the selected entry |
| Shift+T | Toggle label timestamps |
| Enter | Select entry |
| Escape/Ctrl+C | Cancel |
| Ctrl+O | Cycle filter mode |

Filter modes are: default, no-tools, user-only, labeled-only, and all. Configure the default with `treeFilterMode` in [Settings](settings.md).

### Selection Behavior

Selecting a user or custom message:

1. Moves the leaf to the selected message's parent.
2. Places the selected message text in the editor.
3. Lets you edit and resubmit, creating a new branch.

Selecting an assistant, tool, compaction, or other non-user entry:

1. Moves the leaf to that entry.
2. Leaves the editor empty.
3. Lets you continue from that point.

Selecting the root user message resets the leaf to an empty conversation and places the original prompt in the editor.

## `/tree`, `/fork`, and `/clone`

| Feature | `/tree` | `/fork` | `/clone` |
|---------|---------|---------|----------|
| Output | Same session file | New session file | New session file |
| View | Full tree | User-message selector | Current active branch |
| Typical use | Explore alternatives in place | Start a new session from an earlier prompt | Duplicate current work before continuing |
| Summary | Optional branch summary | None | None |

Use `/tree` when you want to keep alternatives together. Use `/fork` or `/clone` when you want a separate session file.

## Branch Summaries

When `/tree` switches away from one branch to another, pi can summarize the abandoned branch and attach that summary at the new position. This preserves important context from the path you left without replaying the whole branch.

When prompted, choose one of:

1. no summary
2. summarize with the default prompt
3. summarize with custom focus instructions

See [Compaction](compaction.md) for branch summarization internals and extension hooks.

## Session Format

Session files are JSONL and contain message entries, model changes, thinking-level changes, labels, compactions, branch summaries, and extension entries.

For parsers, extensions, SDK usage, and the full SessionManager API, see [Session Format](session-format.md).
