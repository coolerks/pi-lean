## 中文译文

### Router 与准备工作

Pi 支持 [llama.cpp](https://github.com/ggml-org/llama.cpp) 的 router server。router 可以发现多个 GGUF 模型，并按需加载/卸载。应使用带 router 支持的当前 llama.cpp 构建版本，构建方式见官方 `docs/build.md`，也可以使用平台的 prebuilt release。

### 启动 router

启动 `llama-server` 时不要传 `--model` 或 `-m`；传入模型会进入单模型模式，不是 router 模式。一个适合本机的起点是：

```bash
llama-server \
  --models-dir ~/models \
  --no-models-autoload \
  --jinja \
  --host 127.0.0.1 \
  --port 8080 \
  -ngl 999 \
  -c 32768
```

`--models-dir` 指定 GGUF 搜索目录；`--no-models-autoload` 要求通过 `/llama` 显式加载；`--jinja` 启用兼容的 chat template 和 tool calling；`-ngl 999` 尽量将层卸载到 GPU；`-c 32768` 设定每个加载模型的 context window，省略时使用模型原生值，可能占用更多内存。

单文件模型可以直接放在目录下；multimodal 和 multi-shard 模型应各放在独立子目录。手动加入模型文件后重启 router。每个模型的 context 大小等高级选项应使用 llama.cpp model presets，而不是把全局 `-c` 当成所有模型的正确值。

### 在 Pi 中连接和管理

启动 Pi 后运行 `/login llama.cpp`，填写 router URL 和可选 API key；默认 URL 是 `http://127.0.0.1:8080`。环境变量方式是 `LLAMA_BASE_URL` 和可选 `LLAMA_API_KEY`。如果 server 开启 key，应让 `--api-key` 与之匹配；本机使用时保留 `--host 127.0.0.1`，不要无意暴露到网络。

`--no-models-autoload` 只保存连接信息；之后执行 `/llama` 加载模型，再用 `/model` 选择当前 session 的模型。`/llama` 中选择未加载模型会加载，选择已加载模型会卸载；`Download model…` 可以搜索 Hugging Face 并选择 repository/quantization，也接受 `owner/repository[:quant]`。加载或下载期间按 Escape 会先确认取消。

Hugging Face 搜索优先使用 `HF_TOKEN`，随后检查 `$HF_TOKEN_PATH`、`$HF_HOME/token`、`$XDG_CACHE_HOME/huggingface/token` 和 `~/.cache/huggingface/token`。不登录也能搜索，但会有更低的 rate limit。gated repository 下载前 Pi 会警告并提供访问页；实际下载由 llama.cpp server 执行，因此 server 进程也必须拥有需要的 `HF_TOKEN`。如果其他模型已加载，Pi 会先询问卸载还是保留；它不会静默卸载或删除模型文件。router 可能被其他客户端共享，所以 `/llama` 显示的是 router 当前状态。

只有已加载模型会出现在 `/model`。router 断开时，`/llama` 提供 **Retry** 和 **Close**；Retry 重新连接并刷新状态，不重放已经中断的操作。

### 故障排查

先检查 endpoint：

```bash
curl http://127.0.0.1:8080/health
curl http://127.0.0.1:8080/models
```

没有模型时检查 `--models-dir`、目录布局并重启 router；模型不在 `/model` 时先用 `/llama` 加载；加载失败或内存不足时降低 `-c` 或卸载其他模型。如果误进入单模型模式，确保启动命令不含 `--model`、`-m` 或 `-hf`。

### 先理解 router 与单模型模式

`llama-server` 有两种容易混淆的启动方式。传入 `--model`、`-m` 或某些 Hugging Face 参数时，服务器直接围绕一个模型运行；不传这些参数并提供 `--models-dir` 时，服务器作为 router 管理多个模型。Pi 的 `/llama` 界面依赖后者提供的模型发现、加载、卸载和状态查询能力。

因此不要只把 URL 填进 Pi 就认为已经完成配置。连接建立只说明 Pi 能访问 server；某个模型是否出现在 `/model`，还取决于它是否已经被 router load。典型流程是：

```text
启动 router
  -> /login llama.cpp 保存 endpoint
  -> /llama 查看未加载模型
  -> 选择模型并等待 load 完成
  -> /model 选择已加载模型
  -> 发送 prompt
```

> 译者注：这里的“加载模型”是服务器进程的资源状态，不是 Pi session 的模型配置。一个 session 可以选择 router 当前已经加载的模型，但 Pi 不负责把 GGUF 文件读入 GPU。Go/Java 客户端也应把连接、模型发现和模型选择分成三个状态，不能把 HTTP 200 当成模型可用。

### 启动参数与资源估算

`--models-dir` 只告诉 router 去哪里发现 GGUF；它不会保证每个文件都能加载。多分片模型必须保留全部 shard，multimodal 模型通常还需要对应 `mmproj` 文件。目录命名清晰有助于在 `/llama` 选择器中区分量化版本，但真正能否加载仍由 llama.cpp 检查模型元数据和硬件能力决定。

`-c 32768` 是每个 loaded model 的 context size。它越大，KV cache 的内存压力越高；在多个模型同时加载时，内存消耗会叠加。`-ngl 999` 表示尽可能把层放到 GPU，但“尽可能”不是保证全部层都能放下。第一次验证建议使用较小模型和较小 `-c`，确认请求链路后再增加上下文。

推荐的本地排查顺序：

1. 先用 `--host 127.0.0.1` 限制为本机访问。
2. 用 `curl /health` 确认进程存活。
3. 用 `curl /models` 确认 router 看到了文件。
4. 在 Pi 中用 `/llama` load 一个小模型。
5. 用 `/model` 选择它，再发送短 prompt。
6. 观察内存、GPU 使用率和 server 日志，再调整 `-c`/`-ngl`。

### Pi 命令和服务器状态

`/login llama.cpp` 负责保存连接信息和可选凭据，`/llama` 负责与 router 交互，`/model` 负责当前 Pi session 的模型选择。把三者混为一个“登录命令”会导致故障定位错误：登录成功但模型列表为空时，应检查 router 和目录，而不是重复输入 API key。

如果 router 被多个客户端共享，Pi 看到的是共享的实时状态。另一客户端可以 load 或 unload 模型，所以 `/llama` 选择器显示的结果可能在两次操作之间变化。Pi 不会静默删除模型文件；卸载只释放运行时资源，下载的 GGUF 仍在磁盘上。

模型下载还涉及两条凭据链：Pi 需要能够调用 router；router 进程本身需要 `HF_TOKEN` 才能下载 gated repository。把 token 只设置在 Pi shell 而没有传给 server，会出现“搜索成功、下载失败”的现象。

### 取消、断开与重试

加载或下载期间按 Escape 会先进入确认流程，确认后取消当前操作。取消表示停止本次请求，不等于删除已经下载的文件，也不一定撤销 server 已经完成的部分工作。若网络在操作中断开，**Retry** 会重新连接并刷新状态；它不是无条件重放原操作，因此可以避免重复下载或重复 load。

> 译者注：这是一个典型的 Harness 语义：连接重试、业务操作重试和外部副作用重试需要分开。Go 的 `context.Context`、Java 的取消 token 只能表达取消意图；如果 server 已经开始加载，客户端必须根据 router 状态决定是否继续，而不是简单地再发一次请求。

### 安全边界

本地服务使用 `127.0.0.1` 可以减少暴露面，但不能替代认证。若改用 `0.0.0.0` 或反向代理，应设置 API key、网络 ACL 和 TLS，并审查 `/models`、下载和推理接口。不要把 `LLAMA_API_KEY` 或 `HF_TOKEN` 写进 session、事件日志、shell 历史分享或教材截图。

### 可执行实验

在临时 `~/models` 中放一个可合法使用的小 GGUF，按文档命令启动 router。记录 `/health`、`/models` 的响应，再在 Pi 中依次执行 `/login llama.cpp`、`/llama` 和 `/model`。故意使用错误端口，观察连接失败；再把 `--models-dir` 指向空目录，区分“服务不可达”和“服务可达但没有模型”。最后在模型加载期间按 Escape，验证取消不会删除源文件。

实验报告应包含：启动参数、模型目录结构、服务器状态变化、Pi 命令、失败信息、恢复动作和安全处理。不要为了完成实验下载需要付费或受限权限的模型。

> 译者注：llama.cpp 页面描述的是 Pi 的集成入口，不是 llama.cpp 全部 API 的参考手册。遇到参数行为变化，要以当前 llama.cpp server 文档和实际 server 版本为准；Pi 端的 `/llama` 语义则以对应源码和本页版本为准。

> 译者注：遇到模型无法加载时，先把问题拆成“文件被发现了吗、router 可达吗、模型能分配资源吗、Pi 是否选中了它”四层；不要把所有错误都归因于 API key。分层诊断比反复重启 Pi 更快。

# llama.cpp

Pi supports the [llama.cpp](https://github.com/ggml-org/llama.cpp) router server. The router discovers multiple GGUF models and loads or unloads them on demand.

Use a current llama.cpp build with router support. Follow the [build instructions](https://github.com/ggml-org/llama.cpp/blob/master/docs/build.md) or install a [prebuilt release](https://github.com/ggml-org/llama.cpp/releases) for your platform.

## Start the router

Start `llama-server` without `--model` or `-m`. Passing a model starts single-model mode instead of router mode.

```bash
llama-server \
  --models-dir ~/models \
  --no-models-autoload \
  --jinja \
  --host 127.0.0.1 \
  --port 8080 \
  -ngl 999 \
  -c 32768
```

Important options:

- `--models-dir ~/models` discovers local GGUF files.
- `--no-models-autoload` keeps loading explicit through `/llama`.
- `--jinja` enables compatible chat templates and tool calling.
- `-ngl 999` offloads as many layers as possible to the GPU.
- `-c 32768` sets the context window for each loaded model. Omit it to use the model's native context, which may require substantially more memory.

A single-file model can sit directly in the model directory. Put multimodal and multi-shard models in separate subdirectories:

```text
~/models/
├── llama-3.2-1b-Q4_K_M.gguf
├── gemma-3-4b-it-Q4_K_M/
│   ├── gemma-3-4b-it-Q4_K_M.gguf
│   └── mmproj-F16.gguf
└── large-model-Q4_K_M/
    ├── large-model-Q4_K_M-00001-of-00003.gguf
    ├── large-model-Q4_K_M-00002-of-00003.gguf
    └── large-model-Q4_K_M-00003-of-00003.gguf
```

Restart the router after manually adding files. For per-model context sizes and other options, use [llama.cpp model presets](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md#model-presets).

## Configure Pi

Start Pi and configure the provider:

```text
/login llama.cpp
```

Enter the router URL and optional API key. The default URL is `http://127.0.0.1:8080`.

If you start the router with `--no-models-autoload`, `/login llama.cpp` only stores the connection. Run `/llama` to load a model, then `/model` to select the loaded model for the current session.

Environment variables can configure the same values without `/login`:

```bash
export LLAMA_BASE_URL=http://127.0.0.1:8080
export LLAMA_API_KEY=optional-secret
pi
```

If the server uses an API key, start `llama-server` with the matching `--api-key` value. Keep `--host 127.0.0.1` for local-only access.

## Manage models

Run:

```text
/llama
```

- Select an unloaded model to load it.
- Select a loaded model to unload it.
- Select **Download model…**, search Hugging Face, then choose a repository and quantization. Exact `owner/repository[:quant]` values also work.
- Press Escape during a load or download to confirm cancellation.

Hugging Face search uses `HF_TOKEN` when set, then checks `$HF_TOKEN_PATH`, `$HF_HOME/token`, `$XDG_CACHE_HOME/huggingface/token`, and `~/.cache/huggingface/token`. Search also works without authentication, subject to lower rate limits. Pi warns before downloading gated repositories and links to their access page. The llama.cpp server performs the download, so its process must also have `HF_TOKEN` when the selected repository requires access.

If other models are loaded, Pi asks whether to unload them first or keep them loaded. Pi does not silently unload models and never deletes model files. The router may be shared with other clients, so `/llama` always displays the router's current state.

Only loaded models appear in `/model`. After loading a model, run `/model` to select it for the current Pi session.

If the router disconnects, `/llama` shows **Retry** and **Close**. Retry reconnects and refreshes model state without replaying the interrupted operation.

## Troubleshooting

Check that the router is reachable:

```bash
curl http://127.0.0.1:8080/health
curl http://127.0.0.1:8080/models
```

- **No models in `/llama`:** Check `--models-dir`, the directory layout, and restart the router.
- **Model missing from `/model`:** Load it with `/llama` first.
- **Load fails or uses too much memory:** Lower `-c` or unload another model.
- **Server is not in router mode:** Start it without `--model`, `-m`, or `-hf`.
