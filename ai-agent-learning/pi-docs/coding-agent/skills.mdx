# Skills

> 本页是 `packages/coding-agent/docs/skills.md` 的中文参考译本，研究 commit 为 `853a80d26c90a14c1886f0ebb8ffaae133ca2185`。API 名称、命令、路径、配置字段和代码标识符保留原样。

## 中文导读

Skill 是按需加载的、面向特定任务的能力包，内容可以包括工作流、安装步骤、辅助脚本、references 和 assets。Pi 实现 Agent Skills standard，但对多数规范问题只告警并继续加载；特别是 Pi 允许 `name` 与父目录名不同，以便多个 Harness 共用一个 Skill 目录。Skill 是资源和指令，不是 Extension 代码，也不是 MCP 传输。

## 源码级中文译文

### 位置、可信度与发现规则

全局 Skill 来自 `~/.pi/agent/skills/` 和 `~/.agents/skills/`；项目 Skill 来自已信任项目中的 `.pi/skills/`、`.agents/skills/` 及祖先目录；package 可以提供 `skills/` 或 `package.json` 的 `pi.skills`，settings 可用 `skills` 数组，命令行可重复使用 `--skill <path>`。`--no-skills` 禁止自动发现，但显式的 `--skill` 路径仍然加载。

`~/.pi/agent/skills/` 和项目 `.pi/skills/` 可以把根目录有效 frontmatter 的 `.md` 当作 Skill；所有位置都递归发现含 `SKILL.md` 的目录。`.agents/skills/` 的根 `.md` 会忽略，分组目录中的有效 `.md` 仍可发现。普通 Markdown 若不像 Skill 会静默忽略。项目资源只在 project trusted 条件满足时加载。

Skill 能让模型执行任意动作，也能携带模型会调用的 executable code，所以使用前必须审阅全部正文、scripts、references 和 assets。路径、脚本和外部网络权限不能因为文件名叫 Skill 就自动获得信任。

### Progressive disclosure 与命令

启动时 Pi 只扫描位置并提取 `name`/`description`，再把可用 Skill 以 XML 形式加入 System Prompt。任务匹配后，模型使用 `read` 读取完整 `SKILL.md`；必要时再按相对路径读取 references/assets。这样 50 个每个 2000 token 的全文不会在每次请求中消耗 100000 token，而只把短 metadata 常驻上下文；代价是模型可能忘记读取，必要时用 `/skill:name` 强制加载。

Skill 注册 `/skill:name` 命令，例如 `/skill:brave-search` 或带参数的 `/skill:pdf-tools extract`。命令后的文本会以 `User: <args>` 追加到 Skill 内容；是否启用命令由 `enableSkillCommands` 控制。Skill 正文中的脚本路径应相对于 Skill 目录，而不是当前项目 cwd。

### 目录和 `SKILL.md` 格式

最小目录包含 `SKILL.md`；可选的 `scripts/` 放 helper、`references/` 放延迟加载的详细文档、`assets/` 放模板和数据。frontmatter 至少需要 `name` 与 `description`；可选 `license`、`compatibility`、`metadata`、`allowed-tools` 和 `disable-model-invocation`。`name` 最多 64 字符，只允许小写字母、数字和连字符，且不能以连字符开头/结尾或包含连续连字符；`description` 最多 1024 字符，应写清能力和触发场景，而不是“helps with PDFs”这类空泛句子。Pi 不强制 name 等于目录名，但标准通常要求二者一致。

frontmatter 通过后，Skill 正文可以自然地用 Setup、Usage 和具体步骤组织；脚本示例中的真实 API/path/参数保持原名。跨 Harness 共用时，可在 settings 中加入 `~/.claude/skills` 或 `~/.codex/skills`，但仍要检查这些目录的信任边界。

### 验证、冲突与示例

Pi 对名称超长、非法字符、连字符问题或 description 超长给 warning；未知 frontmatter 字段忽略。缺 `description` 的 declared Skill 不加载；frontmatter 损坏或没有 description 会 warning 并跳过；同名 Skill 冲突时保留发现顺序中第一个。验证一个 Skill 时要同时检查 metadata、路径、脚本的执行权限、凭据读取、网络调用和 prompt injection。

> 译者注：Java 可以把 Skill discovery 实现为 `Path` 扫描 + YAML frontmatter DTO，Go 可以用 `filepath.WalkDir` + metadata struct；二者都应把“发现”和“读取全文”分成两步，并在把路径交给 Tool 前做 workspace/allowlist 检查。Skill 与 Plugin 的边界是：Skill 主要是按需文本/资源，Plugin 是带生命周期的代码；Skill 与 MCP 的边界是：MCP 是跨进程协议，Skill 不是远程调用协议。

### 可执行步骤

1. 创建一个只含 metadata 的 `SKILL.md`，确认它出现在 System Prompt，但全文没有被预先注入。
2. 用 `read` 读取 Skill，再读取一个 reference；记录每一步 token 和实际路径。
3. 分别测试 `--skill`、`--no-skills`、未信任项目、无 description、非法 name 和同名冲突。
4. 在 fake workspace 中放置带脚本的 Skill，审阅脚本后才执行；验证凭据不会进入日志、Tool Result 或提交记录。

### Discovery 与 progressive disclosure 的执行顺序

Skill discovery 是启动阶段的目录扫描，不是把每个 `SKILL.md` 全文读入 Context。Pi 先收集可用 Skill 的 `name`、`description` 和路径，再以 XML 形式提供简短目录；模型判断任务匹配后，才通过 `read` 读取完整正文，随后按需要读取 `references/` 或 `assets/`。

```text
扫描目录
  -> 解析 frontmatter
  -> 保留 name/description/path
  -> 写入 system prompt 的 Skill 列表
  -> 模型决定需要某项能力
  -> read SKILL.md
  -> read scripts/references/assets
  -> 按相对路径执行工作流
```

这样做不是为了隐藏能力，而是控制 Context 成本。若有 50 个 Skill、每个完整说明 2000 token，常驻全文约 100000 token；只保留平均 30 token 的 metadata，则约 1500 token，模型在需要时再付费加载相关正文。代价是模型可能不主动读取全文，因此任务明确要求时可使用 `/skill:name`。

> 译者注：progressive disclosure 解决的是“什么时候把说明放进 Context”，不是安全隔离。Skill 仍可指示模型执行 shell、读取凭据或访问网络；真正的权限必须在 Tool/Runtime 层决定。Java/Go 实现都应把 discovery 和 content loading 做成两个可测试接口。

### 各个位置的差异

全局位置 `~/.pi/agent/skills/`、`~/.agents/skills/` 影响用户所有项目；项目 `.pi/skills/` 和 `.agents/skills/` 需要 project trust；package 和 settings 是显式资源来源；CLI `--skill <path>` 是 additive 的人工指定。`--no-skills` 关闭自动发现，但不能抵消显式 `--skill`，否则用户无法在临时运行中选择一个明确 Skill。

根目录 Markdown 的规则有意不同：在 `~/.pi/agent/skills/` 和 `.pi/skills/` 中，带有效 Skill frontmatter 且有非空 `description` 的根 `.md` 可作为单文件 Skill；`.agents/skills/` 忽略根 `.md`，但会发现分组目录中的有效 `.md`。所有位置递归寻找目录内的 `SKILL.md`。普通 Markdown 若不符合 Skill 形状会静默忽略，避免把 README 当成可调用能力。

### `SKILL.md` 的文件结构

Skill 目录至少有 `SKILL.md`，其余文件由作者定义。常见布局是 `scripts/` 放辅助程序、`references/` 放按需文档、`assets/` 放模板或数据。正文内的相对路径以 Skill 目录为基准，不以当前项目 cwd 为基准；这使同一个 Skill 从不同仓库调用时仍能找到自己的资源。

```text
review-skill/
├── SKILL.md
├── scripts/check.sh
├── references/style.md
└── assets/template.json
```

一个可执行 Skill 应在正文中分开写 Setup、Usage、输入输出和失败处理；不要只写“运行脚本即可”。脚本需要说明依赖、超时、网络、文件输出和凭据来源。资源文件虽不是 prompt text，也可能包含 prompt injection 或恶意 payload，加载前仍需审阅。

> 译者注：`SKILL.md` 是给模型阅读的说明，不等于宿主已经验证过的计划。把它类比成 Java classpath 上的一份操作手册更合适，而不是已注册的安全 Service。Go 的 `filepath.WalkDir` 或 Java 的 `Files.walk` 只能发现文件，不能替代后续 allowlist 和审批。

### Frontmatter 校验与 name 规则

必填字段是 `name` 和 `description`。`name` 长度 1–64，只允许小写字母、数字和连字符，不能首尾连字符或连续连字符；`description` 最多 1024 字符，应写“做什么以及什么时候使用”。可选字段包括 `license`、`compatibility`、`metadata`、`allowed-tools` 和 `disable-model-invocation`。

Pi 对多数违规只发 warning 并继续，但缺少 description 的 declared Skill 不会加载，损坏的 frontmatter 也会被跳过。未知字段会被忽略。Pi 允许 name 与父目录名不同，这是它与标准的一处有意差异；共享 Skill 目录时这很方便，但会增加路径和名称排查成本。

有效示例：`pdf-processing`、`data-analysis`、`code-review`；无效示例：`PDF-Processing`、`-pdf`、`pdf--processing`。description “Helps with PDFs” 太宽泛，应该写清提取文本、表格、表单和使用场景，帮助模型做出 discovery 决策。

### 冲突、失败与安全检查

同名 Skill 冲突时，Pi 发 warning 并保留发现顺序中第一个。多个目录都存在 `review` 时，不要只看名称，应记录来源路径、scope、发现顺序和实际 `SKILL.md`。验证失败不只看 frontmatter，还应检查：脚本是否可执行、相对路径是否越出 Skill 根目录、是否读取环境凭据、是否连接网络、输出是否包含秘密，以及正文是否试图绕过用户确认。

Skill 可携带任意指令，甚至让模型执行 executable code，所以第三方 Skill 与第三方 Extension 一样需要源代码审查。区别是 Extension 直接运行宿主代码并注册事件/工具；Skill 通常通过文字指导模型使用已有 Tool。MCP 是跨进程协议，Skill 不是 MCP server，也不会因为写出 `tools/call` 就自动拥有远端连接。

> 译者注：安全策略要放在最终 effect 前。即使 Skill 声称“只读”，模型仍可能把路径传给 `bash`；因此 Tool Registry、PermissionPolicy 和 sandbox 必须独立校验。Go/Java 示例中的 skill discovery 只能演示 metadata 和资源读取，不能当作生产隔离。

### 可执行实验：观察一次 Skill 加载

1. 在临时项目创建 `skills/review/SKILL.md`，只写合法 `name`、`description` 和一段正文。
2. 让项目通过 trust，再启动 Pi，记录 system prompt 里出现的 metadata；确认完整正文尚未自动注入。
3. 输入匹配任务，让模型或用户执行 `/skill:review`，使用 `read` 获取全文。
4. 再读取一个 reference，检查路径相对于 Skill 目录解析。
5. 使用坏 name、空 description、重复 name 和缺失文件重复测试，记录 warning 与是否加载。
6. 加入一个脚本但先只审阅，不执行；测试脚本调用的 Tool 是否经过正常权限检查。
7. 对照 `--no-skills` 和显式 `--skill ./path`，确认 additive 规则。

实验报告应包含 discovery path、frontmatter 结果、system prompt 摘要、实际读取文件、token 变化、权限判断和失败日志。不要在实验 Skill 中放 API key、SSH 文件或会修改真实仓库的脚本。

> 译者注：如果模型没有读取 Skill 全文，优先检查 description 是否足够具体、任务是否真正匹配，以及是否启用了 `enableSkillCommands`；不要立刻把全文硬编码进 system prompt。这样会破坏 progressive disclosure 的成本边界。

# Skills

Skills are self-contained capability packages that the agent loads on-demand. A skill provides specialized workflows, setup instructions, helper scripts, and reference documentation for specific tasks.

Pi implements the [Agent Skills standard](https://agentskills.io/specification), warning about most violations but remaining lenient. Pi allows skill names to differ from their parent directory even though the standard disallows it; that rule is suboptimal for shared skill directories used across multiple agent harnesses.

## Locations

> **Security:** Skills can instruct the model to perform any action and may include executable code the model invokes. Review skill content before use.

Pi loads skills from:

- Global:
  - `~/.pi/agent/skills/`
  - `~/.agents/skills/`
- Project (only after the project is trusted):
  - `.pi/skills/`
  - `.agents/skills/` in `cwd` and ancestor directories (up to git repo root, or filesystem root when not in a repo)
- Packages: `skills/` directories or `pi.skills` entries in `package.json`
- Settings: `skills` array with files or directories
- CLI: `--skill <path>` (repeatable, additive even with `--no-skills`)

Discovery rules:
- In `~/.pi/agent/skills/` and `.pi/skills/`, direct root `.md` files are discovered as individual skills when they have valid skill frontmatter with a non-empty `description`
- In all skill locations, directories containing `SKILL.md` are discovered recursively
- In `~/.agents/skills/` and project `.agents/skills/`, root `.md` files are ignored, but nested `.md` files in grouping folders are discovered when they declare skill frontmatter
- Root Markdown files other than `SKILL.md` that do not look like skills are ignored silently

Disable discovery with `--no-skills` (explicit `--skill` paths still load).

  ]

```

```

## How Skills Work

1. At startup, pi scans skill locations and extracts names and descriptions
2. The system prompt includes available skills in XML format per the [specification](https://agentskills.io/integrate-skills)
3. When a task matches, the agent uses `read` to load the full SKILL.md (models don't always do this; use prompting or `/skill:name` to force it)
4. The agent follows the instructions, using relative paths to reference scripts and assets

This is progressive disclosure: only descriptions are always in context, full instructions load on-demand.

## Skill Commands

Skills register as `/skill:name` commands:

```bash
/skill:brave-search           # Load and execute the skill
/skill:pdf-tools extract      # Load skill with arguments
```

Arguments after the command are appended to the skill content as `User: <args>`.

Toggle skill commands via `/settings` in interactive mode or in `settings.json`:

```json
{
  "enableSkillCommands": true
}
```

## Skill Structure

A skill is a directory with a `SKILL.md` file. Everything else is freeform.

```
my-skill/
├── SKILL.md              # Required: frontmatter + instructions
├── scripts/              # Helper scripts
│   └── process.sh
├── references/           # Detailed docs loaded on-demand
│   └── api-reference.md
└── assets/
    └── template.json
```

### SKILL.md Format

````markdown
---
name: my-skill
description: What this skill does and when to use it. Be specific.
---

# My Skill

## Setup

Run once before first use:
```bash
cd /path/to/skill && npm install
```

## Usage

```bash
./scripts/process.sh <input>
```
````

Use relative paths from the skill directory:

```markdown
See [the reference guide](references/REFERENCE.md) for details.
```

## Frontmatter

Per the [Agent Skills specification](https://agentskills.io/specification#frontmatter-required):

| Field | Required | Description |
|-------|----------|-------------|
| `name` | Yes | Max 64 chars. Lowercase a-z, 0-9, hyphens. Unlike the standard, Pi does not require this to match the parent directory because that standard requirement is suboptimal for shared skill directories. |
| `description` | Yes | Max 1024 chars. What the skill does and when to use it. |
| `license` | No | License name or reference to bundled file. |
| `compatibility` | No | Max 500 chars. Environment requirements. |
| `metadata` | No | Arbitrary key-value mapping. |
| `allowed-tools` | No | Space-delimited list of pre-approved tools (experimental). |
| `disable-model-invocation` | No | When `true`, skill is hidden from system prompt. Users must use `/skill:name`. |

### Name Rules

- 1-64 characters
- Lowercase letters, numbers, hyphens only
- No leading/trailing hyphens
- No consecutive hyphens
Pi does not require the name to match the parent directory. The Agent Skills standard does, but that requirement is suboptimal for shared skill directories used by multiple tools.

Valid: `pdf-processing`, `data-analysis`, `code-review`
Invalid: `PDF-Processing`, `-pdf`, `pdf--processing`

### Description Best Practices

The description determines when the agent loads the skill. Be specific.

Good:
```yaml
description: Extracts text and tables from PDF files, fills PDF forms, and merges multiple PDFs. Use when working with PDF documents.
```

Poor:
```yaml
description: Helps with PDFs.
```

## Validation

Pi validates skills against the Agent Skills standard. Most issues produce warnings but still load the skill:

- Name exceeds 64 characters or contains invalid characters
- Name starts/ends with hyphen or has consecutive hyphens
- Description exceeds 1024 characters

Unknown frontmatter fields are ignored.

Declared skills with missing descriptions are not loaded. Malformed `SKILL.md` files and `SKILL.md` files without a description produce warnings and are not loaded. Other Markdown files without valid skill frontmatter are ignored.

Name collisions (same name from different locations) warn and keep the first skill found.
