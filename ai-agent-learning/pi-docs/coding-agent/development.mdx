## 中文译文

### 环境与从源码运行

官方开发流程是 clone 仓库、执行 `npm install` 和 `npm run build`；从源码启动使用 `pi-test.sh`。这个脚本可以从任意调用目录执行，Pi 仍保留调用者的 current working directory，因此 cwd 决定项目指令、Session 和 Tool 的相对路径。当前教材分析工作区的固定 commit；若你在 fork 上开发，应把英文示例中的仓库地址换成自己的地址，不要把这段命令当成必须重新 clone 当前工作区。

### Fork 与重命名

在 `package.json` 的 `piConfig` 中设置 `name`、`configDir` 和 `bin`：`name` 影响 CLI banner，`configDir` 影响配置/Session 位置，`bin` 决定安装后的可执行入口。重命名不只是换标题，还会改变环境变量和用户配置路径；应在干净目录验证迁移行为。

### 路径解析

Pi 有 npm 安装、standalone binary 和从源码运行三种资产布局。访问 package 资源时必须使用 `src/config.ts` 提供的 `getPackageDir`、`getThemeDir` 等 helper，不要直接依赖 `__dirname`。Node 的 ESM、打包后的 binary 和源码路径对 `__dirname` 的假设不同；统一 helper 才能让主题、扩展和其他资源在三种模式下找到。

### 调试与测试

隐藏命令 `/debug` 将渲染后的 TUI 行（含 ANSI code）以及最近发给 LLM 的消息写入 `~/.pi/agent/pi-debug.log`。这对排查布局和请求组装很有用，但日志可能包含项目内容，分享前应脱敏。非 LLM 测试使用 `./test.sh`，不需要 API key；`npm test` 会运行完整测试，指定文件时按项目的 Vitest 命令传路径。不要把真实 Provider 凭据作为单元测试前置条件。

源码包边界包括 `ai`（Provider abstraction）、`agent`（Loop 和 message types）、`tui`（终端组件）与 `coding-agent`（CLI/interactive mode）。进入源码时先沿 package dependency 读接口，再追实现；不要只看最终 TUI 输出推断 Loop 行为。

> 译者注：`pi-test.sh` 保持调用 cwd 类似 Java 进程接收 `user.dir`，而 `configDir` 类似应用级 home。两者决定的资源作用域不同，调试时要分别记录。

# Development

See [AGENTS.md](https://github.com/earendil-works/pi-mono/blob/main/AGENTS.md) for additional guidelines.

## Setup

```bash
git clone https://github.com/earendil-works/pi-mono
cd pi-mono
npm install
npm run build
```

Run from source:

```bash
/path/to/pi-mono/pi-test.sh
```

The script can be run from any directory. Pi keeps the caller's current working directory.

## Forking / Rebranding

Configure via `package.json`:

```json
{
  "piConfig": {
    "name": "pi",
    "configDir": ".pi"
  }
}
```

Change `name`, `configDir`, and `bin` field for your fork. Affects CLI banner, config paths, and environment variable names.

## Path Resolution

Three execution modes: npm install, standalone binary, tsx from source.

**Always use `src/config.ts`** for package assets:

```typescript
import { getPackageDir, getThemeDir } from "./config.js";
```

Never use `__dirname` directly for package assets.

## Debug Command

`/debug` (hidden) writes to `~/.pi/agent/pi-debug.log`:
- Rendered TUI lines with ANSI codes
- Last messages sent to the LLM

## Testing

```bash
./test.sh                         # Run non-LLM tests (no API keys needed)
npm test                          # Run all tests
npm test -- test/specific.test.ts # Run specific test
```

## Project Structure

```
packages/
  ai/           # LLM provider abstraction
  agent/        # Agent loop and message types  
  tui/          # Terminal UI components
  coding-agent/ # CLI and interactive mode
```
