## 中文译文

### 页面范围与核心接口

Pi 可以创建 TUI（终端用户界面）组件。Extension 和自定义 Tool 可以用这些组件向交互式用户显示选择器、进度、状态或完整的输入界面。本页的组件库是 `@earendil-works/pi-tui`，后面的应用级辅助组件来自 `@earendil-works/pi-coding-agent`。

所有组件都实现下面四个约定：

```typescript
interface Component {
  render(width: number): string[];
  handleInput?(data: string): void;
  wantsKeyRelease?: boolean;
  invalidate(): void;
}
```

`render(width)` 返回每行一个字符串的数组，而且每行的显示宽度都不能超过 `width`。可选的 `handleInput` 只在组件拥有焦点时接收键盘输入；`wantsKeyRelease` 设为 `true` 时，组件还会收到 Kitty 键盘协议的按键释放事件，默认是 `false`。`invalidate` 清除缓存的渲染结果，主题改变时 TUI 会调用它。

TUI 在每个已渲染行的末尾追加完整的 SGR reset 和 OSC 8 reset，所以样式不会跨行延续。若一段带 ANSI 样式的文本跨越多行，必须逐行重新应用样式，或者使用 `wrapTextWithAnsi()`，否则后续文字可能继承错误的颜色或链接状态。

### Focusable、IME 与容器焦点

如果组件显示文本光标并需要 IME（输入法编辑器），它应实现 `Focusable`。组件在当前获得焦点时把 `focused` 设为 `true`，在 render 输出中把 `CURSOR_MARKER` 放在模拟光标前。TUI 会扫描这个零宽 APC escape sequence，计算终端硬件光标的位置；只有启用 `showHardwareCursor` 时才显示硬件光标。默认隐藏硬件光标是为了继续使用组件绘制的模拟光标，同时让支持 IME 的终端知道候选窗口应该出现在哪里。某些终端需要可见硬件光标，届时可以设置 `showHardwareCursor`、调用 `setShowHardwareCursor(true)`，或设置 `PI_HARDWARE_CURSOR=1`。内置 `Editor` 和 `Input` 已实现这个接口。

包含 `Input` 或 `Editor` 子组件的 dialog、selector 等容器也必须实现 `Focusable`，并在 setter 中把自己的焦点状态传给子输入框。若只给外层容器设置焦点而不传播，中文、日文、韩文等输入法的候选框会出现在错误位置。这里的关键不是“哪个组件接收字符串”，而是焦点状态、render 光标标记和终端硬件光标必须形成同一条链。

### 在 Extension、Tool 和 overlay 中使用组件

`ctx.ui.custom()` 接收一个 factory。factory 会拿到当前 TUI、theme、keybindings 和 `done` 回调，然后返回一个 `Component` 或兼容的三方法对象。异步调用方等待 `custom` 返回的 Promise；选择、取消和关闭都应在明确的路径调用 `done(value)`，不能让组件只改变内部字段而不通知宿主。

```text
Extension/Tool handler
  -> await ctx.ui.custom(factory)
  -> factory 创建组件并绑定 onSelect/onCancel
  -> handleInput 改变状态并 requestRender
  -> done(value) 结束 UI Promise
```

这里的 TypeScript `async`/`await` 与 Java 的 `CompletableFuture`、listener callback 类似，也可以把 `done` 理解为一次性的 `Consumer<Result>`；Go 中通常用 channel 或显式 callback 把选择结果送回 handler。`ctx.ui.custom` 的取消结果应和业务值区分，例如 `string | null` 中的 `null` 表示用户取消，而不是选中了空字符串。

传入 `{ overlay: true }` 时，组件会叠加在已有内容之上而不清屏。`overlayOptions` 可以用数字或百分比设置 `width`、`minWidth`、`maxHeight`，用 `anchor`、`offsetX`、`offsetY` 或 `row`、`col` 设置位置，用 `margin` 设置边距，并用 `visible(termWidth, termHeight)` 在窄终端隐藏它。`onHandle` 可得到控制句柄：`focus()` 把 overlay 置于视觉前景并接收输入，`unfocus()` 释放焦点，`unfocus({ target })` 把输入交给指定组件，`unfocus({ target: null })` 则有意留下未聚焦状态；`setHidden` 控制可见性，`hide` 永久移除。

一个可见且已聚焦的 overlay 会在临时的非 overlay UI 结束后重新取得输入。如果 overlay 打开另一个普通 `ctx.ui.custom()`，新 UI 活跃期间由新 UI 接收输入；关闭后原 overlay 可以恢复。不要复用已关闭 overlay 的对象引用：关闭会 dispose 组件，旧引用已经失效。正确方式是每次重新调用 factory 创建新实例，而不是把已 dispose 的菜单再次交给 TUI。overlay 的 anchor、margin、stacking、窄窗口和动画可参照 `overlay-qa-tests.ts`。

### 内置组件

`Text` 显示多行文字并负责换行；可设置水平、垂直 padding 和背景函数，并用 `setText` 更新内容。`Box` 是带 padding 和背景色的容器，可以用 `addChild` 放入 `Text`，也可以用 `setBgFn` 更换背景。`Container` 只负责把子组件按垂直方向编排，支持 `addChild` 和 `removeChild`。`Spacer` 产生指定数量的空行。

`Markdown` 负责 Markdown 渲染和语法高亮；创建时传入文本、padding 和 `MarkdownTheme`，更新时调用 `setText`。`Image` 接收 base64 数据、MIME type、`ImageTheme` 和尺寸限制，在 Kitty、iTerm2、Ghostty、WezTerm、Warp 等支持的终端显示图片。图片能力取决于终端协议，不能把“对象创建成功”当成“屏幕一定能显示”。

### 键盘输入、行宽与自定义组件

使用 `matchesKey()` 判断按键，并优先使用 `Key.enter`、`Key.escape`、`Key.up`、`Key.ctrl("c")` 等 `Key` 常量或构造器。也支持 `enter`、`ctrl+c`、`shift+tab`、`ctrl+shift+p` 等字符串格式，但组件应保持一种清晰的写法。选择器通常在上下键改变 `selectedIndex`，Enter 调用 `onSelect`，Escape 调用 `onCancel`。

`render(width)` 的宽度约束是硬规则，不是建议。`visibleWidth` 忽略 ANSI escape sequence 计算显示列数；`truncateToWidth` 进行安全截断并可指定 ellipsis；`wrapTextWithAnsi` 换行时保留样式。不要用 JavaScript 的 `string.length` 或 Go 的字节长度直接代替终端列宽：中文、emoji、组合字符和 ANSI 序列都会使二者不同。

自定义组件通常保存业务状态和可选的 `cachedWidth`、`cachedLines`。当 width 没变且缓存存在时直接返回缓存；上下选择改变后调用 `invalidate`，再由注入的 `tui.requestRender()` 请求下一帧。`handleInput` 是同步 callback，不应在其中等待网络；耗时工作应启动异步任务、显示 loader，并在完成或取消时调用 `done`。

### 主题、缓存失效与性能

在 `renderCall`、`renderResult` 或 `ctx.ui.custom` factory 中使用 callback 提供的 `theme`，不要从全局导入一个可能过期的主题。`theme.fg(color, text)` 设置前景色，`theme.bg(color, text)` 设置背景色。前景 token 包括通用文字、状态、边框、消息、Tool、diff、Markdown、语法高亮、Thinking level 和 `bashMode`；背景 token 包括 selected、search match、user message、custom message 和 Tool 成功/失败/等待状态。Markdown 应通过 `getMarkdownTheme()` 获得专用主题。

自定义组件可以定义自己的小型 theme interface，例如 `selected` 和 `normal` 两个样式函数。关键是保存原始数据，不要只保存已经用旧主题生成的 ANSI 字符串。若构造函数把 `theme.fg("accent", message)` 直接塞进子 `Text`，父容器的普通 `invalidate` 只清缓存而不会重新生成这段旧字符串，换主题后颜色仍然错误。正确实现是在 `invalidate()` 中先调用 `super.invalidate()`，再用当前 theme 重建 children；复杂组件可以 `clear()` 后重新建立整棵子树。

这种 rebuild 模式适用于预先染色的文本、语法高亮和包含主题字符串的复杂布局；如果传入的是 render 时才调用的 theme callback、只是无样式的简单容器，或每次 render 都重新计算，就不需要额外重建。渲染成本较高时应缓存结果，但任何影响布局的 state、width 或主题变化都必须让缓存失效。`PI_TUI_WRITE_LOG` 可以把写到 stdout 的原始 ANSI 流保存到文件，用于排查光标、颜色和换行问题。

### 七类常见交互模式

1. **Selection Dialog（`SelectList`）**：用 `SelectList`、`DynamicBorder` 和 `Container` 组合选择 dialog。设置 selected prefix/text、description、scroll info 和 no-match 的 theme；选择时调用 `done(value)`，取消时调用 `done(null)`。这是“可选择列表”优先复用内置组件的模式。
2. **可取消异步操作（`BorderedLoader`）**：用 `BorderedLoader` 显示 spinner，把 `loader.signal` 传给 `fetchData`，在 `onAbort` 调用 `done(null)`，Promise 成功时返回数据，失败时也走可解释的取消/失败路径。Java 可以把 signal 对应为 cancellation token，Go 可以对应 `context.Context`；仅调用 `Future.cancel(true)` 不代表远端请求一定已经停止。
3. **设置与开关（`SettingsList`）**：用 `SettingItem` 描述 id、label、当前值和值集合；`SettingsList` 负责导航和可选 fuzzy search，值改变 callback 只提交配置变更，关闭 callback 调用 `done`。保存配置和重新渲染是两个动作，不能让 UI 状态冒充已持久化。
4. **持久状态栏**：用 `ctx.ui.setStatus("my-ext", value)` 把 mode/status 放进 footer，用 `undefined` 清除。状态属于宿主布局，不应每次 render 都创建重复组件。
5. **工作指示器**：`setWorkingIndicator` 接收 frames 和 `intervalMs`，可以设置静态帧、自定义动画、空数组隐藏，或不传参数恢复默认 spinner。它只改变普通 streaming 的 working indicator，不改变 compaction 和 retry loader 的内置样式；自定义 frame 必须自己加颜色。
6. **编辑器上下方 Widget 与自定义 Footer**：`setWidget` 可放字符串行或 render factory，并用 `placement: "belowEditor"` 放到编辑器下方；清除时传 `undefined`。`setFooter` factory 接收 `footerData`，可读取 git branch、Extension status，并通过 `onBranchChange` 触发重绘；恢复默认 footer 同样传 `undefined`。这些持久区域必须在 branch、model 或数据变化时请求 render。
7. **自定义 Editor（例如 Vim mode）**：继承 `CustomEditor` 而不是基础 `Editor`，保留应用已有的 abort、退出、模型切换等快捷键。自定义模式只处理自己的按键，其余按键调用 `super.handleInput(data)`；用 factory 接收 `tui`、theme 和 keybindings，并用 `setEditorComponent(undefined)` 恢复默认编辑器。Vim 示例把 Escape 在 insert/normal 两种模式下分别解释，且用 `truncateToWidth` 让 mode indicator 不突破行宽。

这些模式的共同边界是：UI callback 只更新 UI 或报告用户选择，实际 Agent prompt、Tool 执行和 Session 写入仍由宿主控制。一个 loader 的取消应该停止当前等待，并清理对它负责的异步资源；不能关闭整个 TUI 或误取消另一个 run。

### 实现规则与练习

1. 一定使用 factory callback 提供的 `theme`，不要导入全局旧主题。
2. `DynamicBorder` 的颜色函数写成 `(s: string) => theme.fg("accent", s)`，保持 TypeScript 的参数类型明确。
3. state 变化后调用 `tui.requestRender()`；改变字段本身不会自动绘制下一帧。
4. 自定义组件至少返回 `render`、`invalidate`、`handleInput` 三个职责明确的方法；不接收输入时也要有稳定的 no-op 处理策略。
5. 优先使用 `SelectList`、`SettingsList`、`BorderedLoader`，不要复制一份已有组件的焦点、宽度和取消逻辑。

建议实验顺序是：先用 `preset.ts` 完成选择 dialog；再用 `qna.ts` 让一个可取消的异步请求显示 loader；然后用 `tools.ts` 做设置开关；最后阅读 `modal-editor.ts`、`custom-footer.ts`、`working-indicator.ts`、`snake.ts` 和 `todo.ts`。每次实验都记录输入事件、state 变化、`requestRender` 次数、dispose 时机和最终 `done` 值。这样可以同时观察 TypeScript callback/Promise、Java listener/Future、Go callback/channel 与 TUI 生命周期之间的对应关系。

## 深入教程：从接口到可维护组件

上面的译文给出整体结构；本节把源文档里的每一个工程约束拆成可跟读的实现步骤。

### 1. 先建立终端 UI 的心智模型

TUI 不是浏览器 DOM。

它通常没有稳定的节点树。

应用每次 render 都返回若干行带 ANSI 转义序列的字符串。

终端根据光标位置、颜色序列和可见列数把这些字符画出来。

因此组件同时处理三种数据：业务状态、键盘事件和屏幕几何。

业务状态回答“选中了哪一项”。

键盘事件回答“用户刚刚按了什么”。

屏幕几何回答“这一帧能放下多少列和多少行”。

这三者不能混成一个字符串字段。

```text
state + input event + width
              |
              v
          render()
              |
              v
       string[] + ANSI
```

`Component` 是这三种数据之间的最小边界。

`render` 只应该读取状态并生成画面。

`handleInput` 改变状态，但不应该直接写 stdout。

`invalidate` 宣布此前缓存的画面已经不能信任。

TUI 宿主拥有实际绘制时机。

这样做的好处是测试可以直接传入宽度和输入字节。

不需要真的启动一个终端才能测试“向下移动一次”。

> 译者注：Java Swing 中，`JComponent.paintComponent(Graphics)` 类似 `render`，`KeyListener` 类似 `handleInput`。区别是 Swing 通常由 EDT（Event Dispatch Thread）调度重绘，而这里的组件直接返回字符串行。

### 2. Component interface 逐项翻译

源文档的接口如下：

```typescript
interface Component {
  render(width: number): string[];
  handleInput?(data: string): void;
  wantsKeyRelease?: boolean;
  invalidate(): void;
}
```

`render(width)` 的参数是当前可用的终端列数。

它不是“建议宽度”，而是组件必须遵守的上限。

返回数组的每个元素代表一行。

数组长度代表组件需要的高度。

组件不需要在这里返回行号或列号。

容器会把行拼接到父布局中。

`handleInput` 后面的 `?` 表示可选方法。

不接受键盘输入的展示组件可以不实现它。

接受输入的组件必须把输入字节当作事件，而不是当作完整字符假设。

一个 Escape、方向键或 Kitty 键盘事件可能由多个字节组成。

`wantsKeyRelease` 默认是 `false`。

只有需要区分按下和释放的组件才打开它。

例如游戏或需要按住键连续移动的组件可能需要释放事件。

`invalidate()` 没有返回值。

它的语义是“下一次 render 不得继续相信旧缓存”。

它不是“马上重绘”。

要请求马上重绘，使用宿主提供的 `tui.requestRender()`。

```typescript
class Counter implements Component {
  private value = 0;

  render(width: number): string[] {
    return [truncateToWidth(`count=${this.value}`, width)];
  }

  handleInput(data: string): void {
    if (matchesKey(data, Key.up)) this.value++;
  }

  invalidate(): void {}
}
```

这个例子还不完整，因为输入改变后没有请求绘制。

在 `ctx.ui.custom` 中，handler 通常会在调用 `handleInput` 后调用 `tui.requestRender()`。

组件本身只保存状态，宿主决定绘制节奏。

> 译者注：不要把 `invalidate` 理解成 JavaFX 的 `requestLayout`。前者主要清理缓存；后者可能触发布局计算。Pi TUI 中“清缓存”和“申请新帧”是两个动作。

### 3. 行宽规则不是装饰性规则

终端宽度以可见列计算。

ANSI 颜色序列不占列。

中文字符通常占两列。

emoji 和组合字符的宽度依赖终端实现。

所以 JavaScript 的 `text.length` 不能当作屏幕宽度。

Go 的 `len(text)` 也只是 UTF-8 字节数。

```typescript
const raw = theme.fg("accent", "中文");
visibleWidth(raw);       // 可见列数，而不是 raw.length
truncateToWidth(raw, 4); // 不破坏 ANSI 的截断
```

如果组件返回超宽行，父容器无法可靠地对齐后续内容。

overlay 的边框可能被推到屏幕外。

光标位置也可能落在另一行。

正确做法是在进入布局前就限制宽度。

不要先拼接所有内容，再用 `slice(0, width)` 截断。

那会把 ANSI escape sequence 从中间切断。

也不要用 `stripAnsi(text).slice(...)` 后直接返回无样式文本。

那会丢失用户需要的颜色和链接。

```typescript
render(width: number): string[] {
  const title = theme.fg("accent", this.title);
  const safe = truncateToWidth(title, Math.max(0, width - 2), "");
  return [`  ${safe}`];
}
```

这里预留了两个空格给前缀。

截断上限必须扣掉前缀和边框。

> 译者注：如果你熟悉 Java `String.length()`，这里最容易犯的错误就是把 UTF-16 code unit 当成终端 column。Go 也一样，`utf8.RuneCountInString` 仍不等于 East Asian Width。

### 4. Focusable 与 IME 光标

普通组件只需要绘制一个假的光标。

输入法还需要知道真实终端光标在哪里。

`Focusable` 是这个协作协议的入口。

```typescript
import { CURSOR_MARKER, type Focusable } from "@earendil-works/pi-tui";

class TextInput implements Focusable {
  focused = false;
  private value = "";
  private cursor = 0;

  render(width: number): string[] {
    const left = this.value.slice(0, this.cursor);
    const at = this.value[this.cursor] ?? " ";
    const right = this.value.slice(this.cursor + 1);
    const marker = this.focused ? CURSOR_MARKER : "";
    return [truncateToWidth(`> ${left}${marker}\\x1b[7m${at}\\x1b[27m${right}`, width)];
  }

  invalidate(): void {}
}
```

`CURSOR_MARKER` 是零宽 APC escape sequence。

它不是用户可见字符。

TUI 在组件已获得焦点时扫描它。

找到它以后，TUI 可以把硬件 cursor 放到对应列。

默认硬件 cursor 仍然隐藏。

因为组件自己的反色字符负责显示模拟 cursor。

启用 `showHardwareCursor` 后，终端也会显示硬件 cursor。

IME 候选窗口通常依赖硬件 cursor 的位置。

如果位置错误，中文候选框会漂到屏幕左上角或旧行。

这不是输入字符编码问题，而是焦点传播问题。

`Input` 和 `Editor` 已经实现了这套协议。

自定义输入框必须保持同样的生命周期。

焦点获得时设置 `focused = true`。

焦点失去时设置 `focused = false`。

render 每一帧都应该根据当前状态决定是否输出 marker。

不要只在构造函数里计算 marker。

主题或布局变化后，marker 的列位置也可能变化。

### 5. 嵌套容器如何传播焦点

Dialog 往往不是输入框本身。

它可能包含标题、边框、搜索框和列表。

如果宿主把焦点给了 dialog，dialog 还必须把状态传给真正的 `Input`。

```typescript
class SearchDialog extends Container implements Focusable {
  private _focused = false;
  private readonly input = new Input();

  constructor() {
    super();
    this.addChild(this.input);
  }

  get focused(): boolean {
    return this._focused;
  }

  set focused(value: boolean) {
    this._focused = value;
    this.input.focused = value;
  }
}
```

这里 setter 是关键。

只实现 getter 会让外层状态看似正确，但内层输入框仍认为自己未聚焦。

只给 child 设置焦点也不够，因为 overlay manager 管理的是外层组件。

完整链路是：

```text
overlay manager
  -> SearchDialog.focused = true
  -> input.focused = true
  -> render emits CURSOR_MARKER
  -> TUI positions terminal cursor
```

关闭 dialog 时应反向释放焦点。

释放后不能继续让隐藏输入框消费输入。

### 6. `ctx.ui.custom` 的 Promise 生命周期

`ctx.ui.custom` 把同步组件生命周期包装成 Promise。

factory 负责创建组件。

`done` 负责结束 Promise。

`handleInput` 负责处理输入。

`tui.requestRender` 负责申请下一帧。

```typescript
const answer = await ctx.ui.custom<string | null>(
  (tui, theme, keybindings, done) => {
    const component = new MyComponent(theme, keybindings);
    component.onSelect = value => done(value);
    component.onCancel = () => done(null);
    return {
      render: width => component.render(width),
      handleInput: data => {
        component.handleInput(data);
        tui.requestRender();
      },
      invalidate: () => component.invalidate(),
    };
  },
);
```

`string | null` 是一个重要的 API 约定。

字符串表示用户选中了值。

`null` 表示取消。

不能把取消编码成空字符串，否则空字符串可能和合法输入混淆。

`done` 最好只调用一次。

重复调用会让调用方收到不可预测的结果。

异步任务也必须在 done 后停止更新已销毁组件。

```typescript
let closed = false;
const finish = (value: string | null) => {
  if (closed) return;
  closed = true;
  done(value);
};
```

真正的实现还应取消 fetch、timer 或子进程。

只阻止 `done` 重复调用不能停止后台副作用。

> 译者注：TypeScript 的 `Promise` 类似 Java `Future`，但 `done` 是 callback，不是 Promise 本身。Go 中可以用 channel 发送一次结果；关闭 UI 时必须让 producer 看到 context cancellation。

### 7. overlay 是输入层，不只是绘制层

`overlay: true` 表示组件画在已有内容上面。

它通常还有自己的 focus ownership。

`overlayOptions.width` 可以是数字或百分比。

`minWidth` 和 `maxHeight` 用于限制响应式布局。

`anchor` 提供九个锚点位置。

`row` 和 `col` 可以绕过锚点使用绝对或百分比位置。

`offsetX`、`offsetY` 在锚点之后再修正位置。

`margin` 留出安全边距。

`visible` 可以在窄终端直接隐藏 overlay。

```typescript
await ctx.ui.custom(
  (tui, theme, keybindings, done) =>
    new SidePanel(tui, theme, keybindings, done),
  {
    overlay: true,
    overlayOptions: {
      width: "50%",
      minWidth: 40,
      maxHeight: "80%",
      anchor: "right-center",
      offsetX: -2,
      margin: { top: 1, right: 2, bottom: 1, left: 2 },
      visible: (width, height) => width >= 80 && height >= 12,
    },
  },
);
```

百分比相对于终端尺寸计算。

计算后仍要通过最小宽度、最大高度和 margin 校验。

如果最终空间不足，组件应处理空数组或简化布局。

### 8. overlay focus 的优先级

可见 overlay 的 focus 不能只靠“最后创建者”猜测。

TUI 需要记录当前 focus target。

`handle.focus()` 把 overlay 放到视觉前景并获得输入。

`handle.unfocus()` 释放输入，让宿主选择 fallback。

`handle.unfocus({ target })` 指定下一个接收者。

`target: null` 明确表示暂时没有焦点组件。

`setHidden(true)` 隐藏但不一定永久销毁。

`hide()` 则从 overlay 栈中永久移除。

```text
focused overlay A
  -> opens normal custom UI B
  -> B owns input while open
  -> B closes
  -> A reclaims focus
```

如果 A 在 B 关闭期间仍接收事件，两个组件会同时响应。

如果 A 没有被记录为 fallback，B 关闭后输入可能落到主编辑器。

因此 focus 转移必须通过 handle 或宿主 API。

不要在组件内部直接修改全局 focus 栈。

> 译者注：这和 Swing 的 `KeyboardFocusManager` 类似：一个窗口可以暂时拥有焦点，但弹窗关闭后必须恢复明确的 focus owner。仅仅把弹窗从屏幕上删掉不等于完成焦点恢复。

### 9. overlay lifecycle 与 dispose

overlay 关闭后组件会被 dispose。

dispose 后的引用不能重新交给 TUI。

错误写法：

```typescript
let menu: MenuComponent;
await ctx.ui.custom((_, __, ___, done) => {
  menu = new MenuComponent(done);
  return menu;
}, { overlay: true });
setActiveComponent(menu);
```

`menu` 的对象仍然存在，但它的宿主资源已经失效。

可能失效的资源包括 input handler、timer、子组件和 focus registration。

正确写法是把显示操作封装成 factory：

```typescript
const showMenu = () => ctx.ui.custom(
  (_, __, ___, done) => new MenuComponent(done),
  { overlay: true },
);
await showMenu();
await showMenu();
```

第二次调用创建一个全新的组件。

“Back” 操作不是把旧对象复活，而是重新进入显示流程。

动画 timer 必须在 dispose 时取消。

异步请求完成后也不能向已关闭组件写状态。

### 10. 内置 Text、Box、Container、Spacer

`Text` 适合展示会换行的文本。

```typescript
const text = new Text("Hello World", 1, 1, s => bgGray(s));
text.setText("Updated");
```

第一个参数是内容。

第二个参数是水平 padding。

第三个参数是垂直 padding。

第四个参数是可选背景函数。

`setText` 改变内容后，组件需要在下一次 render 重新计算换行。

`Box` 主要提供 padding 和背景。

```typescript
const box = new Box(1, 1, s => bgGray(s));
box.addChild(new Text("Content", 0, 0));
box.setBgFn(s => bgBlue(s));
```

`Container` 不理解业务语义。

它只按垂直顺序管理 child。

`removeChild` 后，child 不再由这个容器渲染。

`Spacer(2)` 返回两行空白。

组合时要把 padding、border 和 width 一起计算。

> 译者注：`Container` 只负责组合，不负责替子组件分配“业务焦点”。这类似 Swing 的 `JPanel`：把 child 放进去不会自动决定哪个控件应该接收键盘事件，焦点策略仍要显式实现。

### 11. Markdown 与 Image

`Markdown` 负责 Markdown 解析和语法高亮。

```typescript
const md = new Markdown(
  "# Title\\n\\nSome **bold** text",
  1,
  1,
  theme,
);
md.setText("Updated markdown");
```

`theme` 必须是 `MarkdownTheme`。

Markdown 的 code block、link、quote 和 heading 都可能占用不同宽度。

不要在 Markdown 输出后再用普通字符串切片截断。

`Image` 使用终端图像协议。

支持 Kitty、iTerm2、Ghostty、WezTerm 和 Warp 等终端。

```typescript
const image = new Image(
  base64Data,
  "image/png",
  theme,
  { maxWidthCells: 80, maxHeightCells: 24 },
);
```

base64 数据必须与 MIME type 匹配。

终端不支持协议时，组件创建成功也不代表图像可见。

应为不支持图片的终端准备文本 fallback。

### 12. Keyboard 输入与 `matchesKey`

不要直接比较原始字符串：

```typescript
if (data === "\\x1b[A") {
  // fragile
}
```

同一个逻辑按键可能因终端、平台或 Kitty protocol 得到不同编码。

使用 `matchesKey` 和 `Key`：

```typescript
handleInput(data: string): void {
  if (matchesKey(data, Key.up)) {
    this.selectedIndex--;
    this.invalidate();
  } else if (matchesKey(data, Key.enter)) {
    this.onSelect?.(this.selectedIndex);
  } else if (matchesKey(data, Key.escape)) {
    this.onCancel?.();
  }
}
```

`Key.ctrl("c")`、`Key.shift("tab")` 和 `Key.ctrlShift("p")` 用来构造组合键。

字符串形式适合配置或简单示例。

项目代码应优先使用 `Key.*`，以便 IDE 自动补全和重构。

输入处理顺序很重要。

先检查更具体的组合键，再检查普通字符。

处理完一个事件后不要继续执行可能冲突的分支。

### 13. Key release

大部分菜单只关心 key press。

因此 `wantsKeyRelease` 保持默认 false。

游戏或连续按键组件可以设置 true。

```typescript
class Game implements Component {
  wantsKeyRelease = true;

  handleInput(data: string): void {
    if (matchesKey(data, Key.left)) this.moveLeft();
  }

  render(width: number): string[] {
    return [truncateToWidth(this.frame(), width)];
  }

  invalidate(): void {}
}
```

不要在 key release 不存在时假定它一定会到达。

终端协议可能不支持该事件。

组件应在丢失 release 的情况下仍保持可恢复状态。

### 14. 一个完整 selector 的状态机

selector 至少有四个状态字段：

`items` 保存选项。

`selected` 保存当前索引。

`cachedWidth` 保存缓存使用的宽度。

`cachedLines` 保存缓存行。

```text
Idle
  --up/down--> SelectionChanged
SelectionChanged
  --invalidate + requestRender--> Idle
Idle
  --enter--> Resolved
Idle
  --escape--> Cancelled
```

实现时把状态变化和副作用分开：

```typescript
class MySelector implements Component {
  private selected = 0;
  private cachedWidth?: number;
  private cachedLines?: string[];
  public onSelect?: (item: string) => void;
  public onCancel?: () => void;

  constructor(private readonly items: string[]) {}

  handleInput(data: string): void {
    if (matchesKey(data, Key.up) && this.selected > 0) {
      this.selected--;
      this.invalidate();
    } else if (matchesKey(data, Key.down)
        && this.selected < this.items.length - 1) {
      this.selected++;
      this.invalidate();
    } else if (matchesKey(data, Key.enter)) {
      this.onSelect?.(this.items[this.selected]);
    } else if (matchesKey(data, Key.escape)) {
      this.onCancel?.();
    }
  }

  render(width: number): string[] {
    if (this.cachedLines && this.cachedWidth === width) {
      return this.cachedLines;
    }
    this.cachedWidth = width;
    this.cachedLines = this.items.map((item, index) => {
      const prefix = index === this.selected ? "> " : "  ";
      return truncateToWidth(prefix + item, width);
    });
    return this.cachedLines;
  }

  invalidate(): void {
    this.cachedWidth = undefined;
    this.cachedLines = undefined;
  }
}
```

`render` 的缓存 key 至少包含 width。

如果主题、语言或数据也会变化，它们也必须进入失效条件。

空列表时不能访问 `items[-1]`。

### 15. Theming 的数据流

主题来自宿主 callback。

组件不应自行 import 一个全局当前主题。

```typescript
renderResult(result, options, theme, context) {
  const title = theme.fg("accent", "Done!");
  const body = theme.fg("muted", result.text);
  return new Text(`${title}\\n${body}`, 0, 0);
}
```

前景 token 包括 `text`、`accent`、`muted`、`success`、`error`、`warning`、边框、消息、Tool、diff、Markdown、syntax、thinking 和 `bashMode`。

背景 token 包括 selected、search match、user message、custom message 以及 Tool 状态。

不要在 extension 中硬编码 ANSI 颜色。

硬编码会绕过用户主题和暗色终端适配。

`getMarkdownTheme()` 用来生成 Markdown 专用样式。

自定义组件可以收窄自己的 theme interface：

```typescript
interface MyTheme {
  selected: (text: string) => string;
  normal: (text: string) => string;
}
```

> 译者注：Theme callback 与 Java Swing 的 `UIManager` 不完全相同。它更像把“当前皮肤”作为依赖注入每个 render；这样同一个组件不需要持有全局可变单例。

### 16. 为什么主题变化必须 invalidate

错误实现把 ANSI 字符串提前生成并缓存：

```typescript
class BadComponent extends Container {
  private content: Text;

  constructor(message: string, theme: Theme) {
    super();
    this.content = new Text(theme.fg("accent", message), 1, 0);
    this.addChild(this.content);
  }
}
```

父类 invalidate 只能清理 child 的 render cache。

它不知道 `content` 的文本已经包含旧主题的 escape code。

所以换主题后画面仍使用旧颜色。

正确实现保存原始 message：

```typescript
class GoodComponent extends Container {
  private readonly message: string;
  private readonly content: Text;

  constructor(message: string) {
    super();
    this.message = message;
    this.content = new Text("", 1, 0);
    this.addChild(this.content);
    this.updateDisplay();
  }

  private updateDisplay(): void {
    this.content.setText(theme.fg("accent", this.message));
  }

  override invalidate(): void {
    super.invalidate();
    this.updateDisplay();
  }
}
```

示例中的 `theme` 应由当前组件环境提供。

如果主题只在 render callback 中调用，就不需要重新建树。

复杂布局可以在 invalidate 时 clear children 再 rebuild。

但 rebuild 必须保持原始 data 不变。

### 17. Debug logging 如何使用

设置 `PI_TUI_WRITE_LOG` 会把写到 stdout 的原始 ANSI 流保存到文件。

```bash
PI_TUI_WRITE_LOG=/tmp/tui-ansi.log npx tsx packages/tui/test/chat-simple.ts
```

日志可以回答：

是否写了完整 SGR reset。

OSC 8 link 是否正确关闭。

光标是否移动到预期行列。

换行后样式是否残留。

overlay 是否清除了底层内容。

不要把包含 token、用户输入或文件内容的日志提交到仓库。

调试时优先用最小 fixture。

把一次按键、一次 render 和一次 done 分开观察。

### 18. Performance：缓存什么，不缓存什么

render 可能每次事件都执行。

Markdown 解析、语法高亮和大列表布局可能很贵。

可缓存与 width 相关的结果：

```typescript
class CachedComponent implements Component {
  private cachedWidth?: number;
  private cachedLines?: string[];

  render(width: number): string[] {
    if (this.cachedLines && this.cachedWidth === width) {
      return this.cachedLines;
    }
    const lines = this.buildLines(width);
    this.cachedWidth = width;
    this.cachedLines = lines;
    return lines;
  }

  invalidate(): void {
    this.cachedWidth = undefined;
    this.cachedLines = undefined;
  }

  private buildLines(width: number): string[] {
    return [truncateToWidth(this.text, width)];
  }
}
```

缓存必须在数据变化、主题变化和宽度变化时失效。

不要为了性能缓存带旧主题的字符串。

不要在 `handleInput` 里同步执行网络请求。

异步任务应交给 loader 或宿主 handler。

过度缓存也会造成内存增长。

大列表可以只计算可见窗口，但必须保持 selection 索引正确。

### 19. 六类常见模式：选择器

Selection Dialog 的职责是把选项、焦点、取消和结果连接起来。

```typescript
const result = await ctx.ui.custom<string | null>((tui, theme, _kb, done) => {
  const container = new Container();
  container.addChild(new DynamicBorder((s: string) => theme.fg("accent", s)));
  const list = new SelectList(items, Math.min(items.length, 10), {
    selectedPrefix: t => theme.fg("accent", t),
    selectedText: t => theme.fg("accent", t),
    description: t => theme.fg("muted", t),
    noMatch: t => theme.fg("warning", t),
  });
  list.onSelect = item => done(item.value);
  list.onCancel = () => done(null);
  container.addChild(list);
  container.addChild(new Text(theme.fg("dim", "↑↓ navigate • enter select • esc cancel"), 1, 0));
  container.addChild(new DynamicBorder((s: string) => theme.fg("accent", s)));
  return {
    render: width => container.render(width),
    invalidate: () => container.invalidate(),
    handleInput: data => {
      list.handleInput(data);
      tui.requestRender();
    },
  };
});
```

上边框和下边框都属于布局。

列表的高度要受到 terminal height 限制。

`SelectList` 已经处理了 selection、scroll 和 no-match。

不要重新实现一份只支持鼠标的列表。

结果返回后，宿主再决定是否修改 editor 或 session。

### 20. 六类常见模式：异步 loader 与取消

`BorderedLoader` 适合一个需要等待的操作。

```typescript
const result = await ctx.ui.custom<string | null>((tui, theme, _kb, done) => {
  const loader = new BorderedLoader(tui, theme, "Fetching data...");
  loader.onAbort = () => done(null);
  fetchData(loader.signal)
    .then(value => done(value))
    .catch(() => done(null));
  return loader;
});
```

Escape 应触发 abort，而不是只隐藏 spinner。

`loader.signal` 必须传到 fetch 或其他 cancellable API。

网络 Promise 拒绝时应有明确的失败路径。

`done(null)` 的语义应和成功结果区分。

Java 可以使用 cancellation token 和 interruptible HTTP。

Go 可以把 signal 映射为 `context.Context`。

> 译者注：`AbortSignal` 只表达取消意图。它不能保证远端已经停止计费或撤销数据库副作用；因此 tool/hook 仍需要自己的幂等和回滚策略。

### 21. 六类常见模式：SettingsList

设置界面处理的是键值状态，不是普通选择。

```typescript
const settingsList = new SettingsList(
  items,
  Math.min(items.length + 2, 15),
  getSettingsListTheme(),
  (id, value) => ctx.ui.notify(`${id} = ${value}`, "info"),
  () => done(undefined),
  { enableSearch: true },
);
```

`SettingItem` 应包含稳定 id。

label 是给用户看的文字。

currentValue 是当前值。

values 是允许切换的集合。

值变化 callback 不等同于写磁盘。

需要持久化时必须调用 settings API，并处理写失败。

关闭 callback 只表示 UI 结束。

fuzzy search 只改变可见候选，不应改变真实设置。

### 22. 六类常见模式：状态与工作指示器

`setStatus` 适合持久显示扩展状态：

```typescript
ctx.ui.setStatus("my-ext", ctx.ui.theme.fg("accent", "● active"));
ctx.ui.setStatus("my-ext", undefined);
```

id 必须由 extension 稳定拥有。

清除时传 `undefined`。

不要每一帧重复注册一个 status。

`setWorkingIndicator` 只定制普通 streaming indicator：

```typescript
ctx.ui.setWorkingIndicator({
  frames: ["·", "•", "●", "•"],

```

空 frames 隐藏 indicator。

compaction 和 retry loader 不受这个设置影响。

### 23. 六类常见模式：Widget 与 Footer

Widget 可以显示待办、进度或模式提示。

```typescript
ctx.ui.setWidget("todo", (tui, theme) => ({
  render: () => items.map(item =>
    item.done
      ? theme.fg("success", "✓ " + item.text)
      : theme.fg("dim", "○ " + item.text),
  ),
  invalidate: () => {},
}));
ctx.ui.setWidget("todo", undefined);
```

默认 widget 在 editor 上方。

`placement: "belowEditor"` 把它放到 editor 下方。

widget 的 render 应保持行宽约束。

Footer factory 可以读取 branch 和 extension statuses：

```typescript
ctx.ui.setFooter((tui, theme, footerData) => ({
  invalidate() {},
  render(width) {
    const branch = footerData.getGitBranch() ?? "no git";
    return [truncateToWidth(`${ctx.model?.id} (${branch})`, width)];
  },
  dispose: footerData.onBranchChange(() => tui.requestRender()),
}));
```

`dispose` 用来取消 branch listener。

恢复默认 footer 时传 `undefined`。

### 24. 六类常见模式：自定义 Editor

自定义 editor 适合 modal editing 或特殊 keymap。

必须继承 `CustomEditor`，这样应用级 escape、退出和模型切换行为仍然存在。

```typescript
type Mode = "normal" | "insert";

class VimEditor extends CustomEditor {
  private mode: Mode = "insert";

  handleInput(data: string): void {
    if (matchesKey(data, "escape")) {
      if (this.mode === "insert") {
        this.mode = "normal";
        return;
      }
      super.handleInput(data);
      return;
    }
    if (this.mode === "insert") {
      super.handleInput(data);
      return;
    }
    if (data === "i") { this.mode = "insert"; return; }
    if (data === "h") { super.handleInput("\\x1b[D"); return; }
    if (data === "j") { super.handleInput("\\x1b[B"); return; }
    if (data === "k") { super.handleInput("\\x1b[A"); return; }
    if (data === "l") { super.handleInput("\\x1b[C"); return; }
    if (data.length === 1 && data.charCodeAt(0) >= 32) return;
    super.handleInput(data);
  }
}
```

未处理的控制键必须交回父类。

否则 ctrl+c、ctrl+d 和模型切换可能失效。

`setEditorComponent` 接收 factory，而不是一个长期复用的实例。

恢复默认 editor 传 `undefined`。

### 25. Patterns 之间如何选择

先问需求是一次性结果还是持久状态。

一次性选择使用 `ctx.ui.custom` 和 `SelectList`。

持续状态使用 `setStatus` 或 `setWidget`。

等待网络使用 `BorderedLoader`。

修改输入语义才替换 `CustomEditor`。

不要用 overlay 代替所有布局。

不要用 widget 承担必须确认的 destructive action。

不要在 footer 里执行模型请求。

> 译者注：这些模式相当于后端里的边界设计。把所有逻辑写进一个 handler，就像把 HTTP、事务、数据库和消息发送都塞进 Controller；短期能跑，取消、测试和恢复都会变难。

### 26. Key Rules 逐条复核

规则一：始终使用 callback 提供的 theme。

原因是当前会话可能切换主题。

规则二：`DynamicBorder` 的参数写出 `string` 类型。

原因是 TypeScript 的上下文推断在复杂 factory 中可能丢失。

```typescript
new DynamicBorder((s: string) => theme.fg("accent", s));
```

规则三：state 改变后调用 `tui.requestRender()`。

原因是状态字段改变不会自动刷新 stdout。

规则四：自定义组件返回 `render`、`invalidate`、`handleInput`。

原因是宿主需要统一管理生命周期。

规则五：优先复用 `SelectList`、`SettingsList` 和 `BorderedLoader`。

原因是它们已经处理宽度、焦点、滚动和取消边界。

### 28. 异步竞态测试

最常见竞态是请求完成与用户取消同时发生。

测试必须决定哪个事件获胜。

```text

  -> user presses escape
  -> signal.abort()
  -> request rejects or resolves
  -> done called exactly once
  -> disposed component receives no update
```

### 32. 常见错误的完整 trace

错误一：超宽输出。

```text
render(40)
  -> string.length() <= 40
  -> visibleWidth(string) == 52
  -> border shifts right
```

修复：使用 `visibleWidth` 和 `truncateToWidth`。

错误二：状态改变但没有 render。

```text
selected = 2
  -> no requestRender
  -> terminal still shows selected = 1
```

修复：状态变化后 invalidate，再 requestRender。

错误三：overlay 关闭后仍接收输入。

```text
closed overlay
  -> stale reference keeps handler
  -> key triggers disposed component
```

修复：通过 host lifecycle 创建新实例并清理 handler。

错误四：主题更新不生效。

```text
old theme.fg() string cached in Text
  -> invalidate child cache only
  -> old ANSI code remains
```

修复：保存原始文本，在 invalidate 中重建样式。

错误五：取消只关闭 spinner。

```text
spinner hidden
  -> fetch still running
  -> completion writes to disposed UI
```

修复：传播 `AbortSignal`，并用一次性 finish guard。

# TUI Components

Extensions and custom tools can render custom TUI components for interactive user interfaces. This page covers the component system and available building blocks.

**Source:** [`@earendil-works/pi-tui`](https://github.com/earendil-works/pi-mono/tree/main/packages/tui)

## Component Interface

All components implement:

```typescript
interface Component {
  render(width: number): string[];
  handleInput?(data: string): void;
  wantsKeyRelease?: boolean;
  invalidate(): void;
}
```

| Method | Description |
|--------|-------------|
| `render(width)` | Return array of strings (one per line). Each line **must not exceed `width`**. |
| `handleInput?(data)` | Receive keyboard input when component has focus. |
| `wantsKeyRelease?` | If true, component receives key release events (Kitty protocol). Default: false. |
| `invalidate()` | Clear cached render state. Called on theme changes. |

The TUI appends a full SGR reset and OSC 8 reset at the end of each rendered line. Styles do not carry across lines. If you emit multi-line text with styling, reapply styles per line or use `wrapTextWithAnsi()` so styles are preserved for each wrapped line.

## Focusable Interface (IME Support)

Components that display a text cursor and need IME (Input Method Editor) support should implement the `Focusable` interface:

```typescript
import { CURSOR_MARKER, type Component, type Focusable } from "@earendil-works/pi-tui";

class MyInput implements Component, Focusable {
  focused: boolean = false;  // Set by TUI when focus changes
  
  render(width: number): string[] {
    const marker = this.focused ? CURSOR_MARKER : "";
    // Emit marker right before the fake cursor
    return [`> ${beforeCursor}${marker}\x1b[7m${atCursor}\x1b[27m${afterCursor}`];
  }
}
```

When a `Focusable` component has focus, TUI:
1. Sets `focused = true` on the component
2. Scans rendered output for `CURSOR_MARKER` (a zero-width APC escape sequence)
3. Positions the hardware terminal cursor at that location
4. Shows the hardware cursor only when `showHardwareCursor` is enabled

The cursor remains hidden by default. This keeps the fake cursor rendering, while still positioning the hardware cursor for terminals that track IME candidate windows with hidden cursors. Some terminals require a visible hardware cursor for IME positioning; enable it with `showHardwareCursor`, `setShowHardwareCursor(true)`, or `PI_HARDWARE_CURSOR=1`. The `Editor` and `Input` built-in components already implement this interface.

### Container Components with Embedded Inputs

When a container component (dialog, selector, etc.) contains an `Input` or `Editor` child, the container must implement `Focusable` and propagate the focus state to the child. Otherwise, the hardware cursor won't be positioned correctly for IME input.

```typescript
import { Container, type Focusable, Input } from "@earendil-works/pi-tui";

class SearchDialog extends Container implements Focusable {
  private searchInput: Input;

  // Focusable implementation - propagate to child input for IME cursor positioning
  private _focused = false;
  get focused(): boolean {
    return this._focused;
  }
  set focused(value: boolean) {
    this._focused = value;
    this.searchInput.focused = value;
  }

  constructor() {
    super();
    this.searchInput = new Input();
    this.addChild(this.searchInput);
  }
}
```

Without this propagation, typing with an IME (Chinese, Japanese, Korean, etc.) will show the candidate window in the wrong position on screen.

## Overlays

Overlays render components on top of existing content without clearing the screen. Pass `{ overlay: true }` to `ctx.ui.custom()`:

```typescript
const result = await ctx.ui.custom<string | null>(
  (tui, theme, keybindings, done) => new MyDialog({ onClose: done }),
  { overlay: true }
);
```

For positioning and sizing, use `overlayOptions`:

```typescript
const result = await ctx.ui.custom<string | null>(
  (tui, theme, keybindings, done) => new SidePanel({ onClose: done }),
  {
    overlay: true,
    overlayOptions: {
      // Size: number or percentage string
      width: "50%",          // 50% of terminal width
      minWidth: 40,          // minimum 40 columns
      maxHeight: "80%",      // max 80% of terminal height

      // Position: anchor-based (default: "center")
      anchor: "right-center", // 9 positions: center, top-left, top-center, etc.
      offsetX: -2,            // offset from anchor
      offsetY: 0,

      // Or percentage/absolute positioning
      row: "25%",            // 25% from top
      col: 10,               // column 10

      // Margins
      margin: 2,             // all sides, or { top, right, bottom, left }

      // Responsive: hide on narrow terminals
      visible: (termWidth, termHeight) => termWidth >= 80,
    },
    // Get handle for programmatic focus and visibility control
    onHandle: (handle) => {
      // handle.focus() - focus this overlay and bring it to the visual front
      // handle.unfocus() - release input to normal fallback
      // handle.unfocus({ target }) - release input to a specific component or null
      // handle.setHidden(true/false) - toggle visibility
      // handle.hide() - permanently remove
    },
  }
);
```

### Overlay Focus

A focused visible overlay keeps input ownership across temporary non-overlay UI. If an overlay opens another `ctx.ui.custom()` component without `{ overlay: true }`, that replacement UI receives input while it is active; when it closes, the focused overlay can reclaim input.

Use `handle.unfocus()` when a visible overlay should stop owning input and let TUI fall back to another visible capturing overlay or the previous focus target. Use `handle.unfocus({ target })` when a specific component should receive input while the overlay stays visible. Passing `{ target: null }` intentionally leaves no focused component until focus is set again.

### Overlay Lifecycle

Overlay components are disposed when closed. Don't reuse references - create fresh instances:

```typescript
// Wrong - stale reference
let menu: MenuComponent;
await ctx.ui.custom((_, __, ___, done) => {
  menu = new MenuComponent(done);
  return menu;
}, { overlay: true });
setActiveComponent(menu);  // Disposed

// Correct - re-call to re-show
const showMenu = () => ctx.ui.custom((_, __, ___, done) => 
  new MenuComponent(done), { overlay: true });

await showMenu();  // First show
await showMenu();  // "Back" = just call again
```

See [overlay-qa-tests.ts](../examples/extensions/overlay-qa-tests.ts) for comprehensive examples covering anchors, margins, stacking, responsive visibility, and animation.

## Keyboard Input

Use `matchesKey()` for key detection:

```typescript
import { matchesKey, Key } from "@earendil-works/pi-tui";

handleInput(data: string) {
  if (matchesKey(data, Key.up)) {
    this.selectedIndex--;
  } else if (matchesKey(data, Key.enter)) {
    this.onSelect?.(this.selectedIndex);
  } else if (matchesKey(data, Key.escape)) {
    this.onCancel?.();
  } else if (matchesKey(data, Key.ctrl("c"))) {
    // Ctrl+C
  }
}
```

**Key identifiers** (use `Key.*` for autocomplete, or string literals):
- Basic keys: `Key.enter`, `Key.escape`, `Key.tab`, `Key.space`, `Key.backspace`, `Key.delete`, `Key.home`, `Key.end`
- Arrow keys: `Key.up`, `Key.down`, `Key.left`, `Key.right`
- With modifiers: `Key.ctrl("c")`, `Key.shift("tab")`, `Key.alt("left")`, `Key.ctrlShift("p")`
- String format also works: `"enter"`, `"ctrl+c"`, `"shift+tab"`, `"ctrl+shift+p"`

## Creating Custom Components

Example: Interactive selector

```typescript
import {
  matchesKey, Key,
  truncateToWidth, visibleWidth
} from "@earendil-works/pi-tui";

class MySelector {
  private items: string[];
  private selected = 0;
  private cachedWidth?: number;
  private cachedLines?: string[];
  
  public onSelect?: (item: string) => void;
  public onCancel?: () => void;

  constructor(items: string[]) {
    this.items = items;
  }

  handleInput(data: string): void {
    if (matchesKey(data, Key.up) && this.selected > 0) {
      this.selected--;
      this.invalidate();
    } else if (matchesKey(data, Key.down) && this.selected < this.items.length - 1) {
      this.selected++;
      this.invalidate();
    } else if (matchesKey(data, Key.enter)) {
      this.onSelect?.(this.items[this.selected]);
    } else if (matchesKey(data, Key.escape)) {
      this.onCancel?.();
    }
  }

  render(width: number): string[] {
    if (this.cachedLines && this.cachedWidth === width) {
      return this.cachedLines;
    }

    this.cachedLines = this.items.map((item, i) => {
      const prefix = i === this.selected ? "> " : "  ";
      return truncateToWidth(prefix + item, width);
    });
    this.cachedWidth = width;
    return this.cachedLines;
  }

  invalidate(): void {
    this.cachedWidth = undefined;
    this.cachedLines = undefined;
  }
}
```

Usage in an extension:

```typescript
pi.registerCommand("pick", {
  description: "Pick an item",
  handler: async (_args, ctx) => {
    const items = ["Option A", "Option B", "Option C"];
    const selected = await ctx.ui.custom<string | null>((tui, _theme, _keybindings, done) => {
      const selector = new MySelector(items);
      selector.onSelect = done;
      selector.onCancel = () => done(null);

      return {
        render: (width) => selector.render(width),
        handleInput: (data) => {
          selector.handleInput(data);
          tui.requestRender();
        },
        invalidate: () => selector.invalidate(),
      };
    });

    if (selected !== null) {
      ctx.ui.notify(`Selected: ${selected}`, "info");
    }
  }
});
```

## Performance

Cache rendered output when possible:

```typescript
class CachedComponent {
  private cachedWidth?: number;
  private cachedLines?: string[];

  render(width: number): string[] {
    if (this.cachedLines && this.cachedWidth === width) {
      return this.cachedLines;
    }
    // ... compute lines ...
    this.cachedWidth = width;
    this.cachedLines = lines;
    return lines;
  }

  invalidate(): void {
    this.cachedWidth = undefined;
    this.cachedLines = undefined;
  }
}
```

Call `invalidate()` when state changes, then use the injected `tui.requestRender()` to trigger re-render.

## Invalidation and Theme Changes

When the theme changes, the TUI calls `invalidate()` on all components to clear their caches. Components must properly implement `invalidate()` to ensure theme changes take effect.

### The Problem

If a component pre-bakes theme colors into strings (via `theme.fg()`, `theme.bg()`, etc.) and caches them, the cached strings contain ANSI escape codes from the old theme. Simply clearing the render cache isn't enough if the component stores the themed content separately.

**Wrong approach** (theme colors won't update):

```typescript
class BadComponent extends Container {
  private content: Text;

  constructor(message: string, theme: Theme) {
    super();
    // Pre-baked theme colors stored in Text component
    this.content = new Text(theme.fg("accent", message), 1, 0);
    this.addChild(this.content);
  }
  // No invalidate override - parent's invalidate only clears
  // child render caches, not the pre-baked content
}
```

### The Solution

Components that build content with theme colors must rebuild that content when `invalidate()` is called:

```typescript
class GoodComponent extends Container {
  private message: string;
  private content: Text;

  constructor(message: string) {
    super();
    this.message = message;
    this.content = new Text("", 1, 0);
    this.addChild(this.content);
    this.updateDisplay();
  }

  private updateDisplay(): void {
    // Rebuild content with current theme
    this.content.setText(theme.fg("accent", this.message));
  }

  override invalidate(): void {
    super.invalidate();  // Clear child caches
    this.updateDisplay(); // Rebuild with new theme
  }
}
```

### Pattern: Rebuild on Invalidate

For components with complex content:

```typescript
class ComplexComponent extends Container {
  private data: SomeData;

  constructor(data: SomeData) {
    super();
    this.data = data;
    this.rebuild();
  }

  private rebuild(): void {
    this.clear();  // Remove all children

    // Build UI with current theme
    this.addChild(new Text(theme.fg("accent", theme.bold("Title")), 1, 0));
    this.addChild(new Spacer(1));

    for (const item of this.data.items) {
      const color = item.active ? "success" : "muted";
      this.addChild(new Text(theme.fg(color, item.label), 1, 0));
    }
  }

  override invalidate(): void {
    super.invalidate();
    this.rebuild();
  }
}
```

### When This Matters

This pattern is needed when:

1. **Pre-baking theme colors** - Using `theme.fg()` or `theme.bg()` to create styled strings stored in child components
2. **Syntax highlighting** - Using `highlightCode()` which applies theme-based syntax colors
3. **Complex layouts** - Building child component trees that embed theme colors

This pattern is NOT needed when:

1. **Using theme callbacks** - Passing functions like `(text) => theme.fg("accent", text)` that are called during render
2. **Simple containers** - Just grouping other components without adding themed content
3. **Stateless render** - Computing themed output fresh in every `render()` call (no caching)

## Common Patterns

These patterns cover the most common UI needs in extensions. **Copy these patterns instead of building from scratch.**

### Pattern 1: Selection Dialog (SelectList)

For letting users pick from a list of options. Use `SelectList` from `@earendil-works/pi-tui` with `DynamicBorder` for framing.

```typescript
import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";
import { DynamicBorder } from "@earendil-works/pi-coding-agent";
import { Container, type SelectItem, SelectList, Text } from "@earendil-works/pi-tui";

pi.registerCommand("pick", {
  handler: async (_args, ctx) => {
    const items: SelectItem[] = [
      { value: "opt1", label: "Option 1", description: "First option" },
      { value: "opt2", label: "Option 2", description: "Second option" },
      { value: "opt3", label: "Option 3" },  // description is optional
    ];

    const result = await ctx.ui.custom<string | null>((tui, theme, _kb, done) => {
      const container = new Container();

      // Top border
      container.addChild(new DynamicBorder((s: string) => theme.fg("accent", s)));

      // Title
      container.addChild(new Text(theme.fg("accent", theme.bold("Pick an Option")), 1, 0));

      // SelectList with theme
      const selectList = new SelectList(items, Math.min(items.length, 10), {
        selectedPrefix: (t) => theme.fg("accent", t),
        selectedText: (t) => theme.fg("accent", t),
        description: (t) => theme.fg("muted", t),
        scrollInfo: (t) => theme.fg("dim", t),
        noMatch: (t) => theme.fg("warning", t),
      });
      selectList.onSelect = (item) => done(item.value);
      selectList.onCancel = () => done(null);
      container.addChild(selectList);

      // Help text
      container.addChild(new Text(theme.fg("dim", "↑↓ navigate • enter select • esc cancel"), 1, 0));

      // Bottom border
      container.addChild(new DynamicBorder((s: string) => theme.fg("accent", s)));

      return {
        render: (w) => container.render(w),
        invalidate: () => container.invalidate(),
        handleInput: (data) => { selectList.handleInput(data); tui.requestRender(); },
      };
    });

    if (result) {
      ctx.ui.notify(`Selected: ${result}`, "info");
    }
  },
});
```

### Pattern 7: Custom Editor (vim mode, etc.)

Replace the main input editor with a custom implementation. Useful for modal editing (vim), different keybindings (emacs), or specialized input handling.

```typescript
import { CustomEditor, type ExtensionAPI } from "@earendil-works/pi-coding-agent";
import { matchesKey, truncateToWidth } from "@earendil-works/pi-tui";

type Mode = "normal" | "insert";

class VimEditor extends CustomEditor {
  private mode: Mode = "insert";

  handleInput(data: string): void {
    // Escape: switch to normal mode, or pass through for app handling
    if (matchesKey(data, "escape")) {
      if (this.mode === "insert") {
        this.mode = "normal";
        return;
      }
      // In normal mode, escape aborts agent (handled by CustomEditor)
      super.handleInput(data);
      return;
    }

    // Insert mode: pass everything to CustomEditor
    if (this.mode === "insert") {
      super.handleInput(data);
      return;
    }

    // Normal mode: vim-style navigation
    switch (data) {
      case "i": this.mode = "insert"; return;
      case "h": super.handleInput("\x1b[D"); return; // Left
      case "j": super.handleInput("\x1b[B"); return; // Down
      case "k": super.handleInput("\x1b[A"); return; // Up
      case "l": super.handleInput("\x1b[C"); return; // Right
    }
    // Pass unhandled keys to super (ctrl+c, etc.), but filter printable chars
    if (data.length === 1 && data.charCodeAt(0) >= 32) return;
    super.handleInput(data);
  }

  render(width: number): string[] {
    const lines = super.render(width);
    // Add mode indicator to bottom border (use truncateToWidth for ANSI-safe truncation)
    if (lines.length > 0) {
      const label = this.mode === "normal" ? " NORMAL " : " INSERT ";
      const lastLine = lines[lines.length - 1]!;
      // Pass "" as ellipsis to avoid adding "..." when truncating
      lines[lines.length - 1] = truncateToWidth(lastLine, width - label.length, "") + label;
    }
    return lines;
  }
}

export default function (pi: ExtensionAPI) {
  pi.on("session_start", (_event, ctx) => {
    // Factory receives the TUI, theme, and keybindings from the app
    ctx.ui.setEditorComponent((tui, theme, keybindings) =>
      new VimEditor(tui, theme, keybindings)
    );
  });
}
```

**Key points:**

- **Extend `CustomEditor`** (not base `Editor`) to get app keybindings (escape to abort, ctrl+d to exit, model switching, etc.)
- **Call `super.handleInput(data)`** for keys you don't handle
- **Factory pattern**: `setEditorComponent` receives a factory function that gets `tui`, `theme`, and `keybindings`
- **Pass `undefined`** to restore the default editor: `ctx.ui.setEditorComponent(undefined)`

**Examples:** [modal-editor.ts](../examples/extensions/modal-editor.ts)

## Key Rules

1. **Always use theme from callback** - Don't import theme directly. Use `theme` from the `ctx.ui.custom((tui, theme, keybindings, done) => ...)` callback.

2. **Always type DynamicBorder color param** - Write `(s: string) => theme.fg("accent", s)`, not `(s) => theme.fg("accent", s)`.

3. **Call tui.requestRender() after state changes** - In `handleInput`, call `tui.requestRender()` after updating state.

4. **Return the three-method object** - Custom components need `{ render, invalidate, handleInput }`.

5. **Use existing components** - `SelectList`, `SettingsList`, `BorderedLoader` cover 90% of cases. Don't rebuild them.
