# Windows 设置

> 本页根据 `packages/coding-agent/docs/windows.md` 重新翻译，研究基线为 commit `853a80d26c90a14c1886f0ebb8ffaae133ca2185`。命令、路径、配置字段和工具名称保持原样。

## 中文译文

Pi 在 Windows 上默认使用 Git Bash，并按以下顺序查找可执行文件：

1. `~/.pi/agent/settings.json` 中配置的自定义路径；
2. Git Bash：`C:\Program Files\Git\bin\bash.exe`；
3. PATH 中的 `bash.exe`，可能来自 Cygwin、MSYS2 或 WSL。

对大多数用户来说，安装 [Git for Windows](https://git-scm.com/download/win) 就足够了。实际选择仍取决于设置文件和启动 Pi 的环境，不能只因为 PATH 中存在 `bash.exe` 就断定 Pi 一定会使用它。

## PowerShell 工具

可选的 `powershell` 工具在可用时通过 `pwsh.exe` 执行命令，否则回退到 Windows PowerShell。它使用以下启动参数：

```text
-NoProfile -NonInteractive -ExecutionPolicy Bypass
```

这几个参数分别表示不加载用户 profile、不等待交互输入，以及请求当前进程绕过普通脚本执行策略。管理员或组织策略仍可能优先于命令行参数，所以 `Bypass` 不是安全隔离，也不等于获得管理员权限。

使用 `defaultTools` 替换模型可见的 `bash`：

```json
{
  "defaultTools": ["read", "powershell", "edit", "write"]
}
```

也可以同时启用两个工具以比较行为：

```json
{
  "defaultTools": ["read", "bash", "powershell", "edit", "write"]
}
```

配置 `defaultTools` 只影响模型可调用的工具。编辑器中的 `!` 和 `!!` 命令仍使用 Bash，因此从列表删除 `bash` 不会把用户命令转换成 PowerShell。

> 译者注：可以把 `defaultTools` 看作加入模型请求的能力列表，把 `!`/`!!` 看作 CLI/TUI 的另一条本地执行通道。两者都可能启动 shell，但调用方和生命周期不同。

## 自定义 Bash 路径

```json
{
  "shellPath": "C:\\cygwin64\\bin\\bash.exe"
}
```

修改 `shellPath` 后，Pi 会使用这个路径作为 Bash。JSON 中的双反斜杠表示实际路径中的单个反斜杠。常见错误是忘记 JSON 转义，或者把 Git Bash、WSL 和 Windows 的路径格式混用。

如果需要排查路径，先在启动 Pi 的同一个终端中运行：

```powershell
Get-Command bash.exe
where.exe bash.exe
bash.exe --version
```

如果未设置自定义路径，检查结果可以帮助确认 PATH 候选；如果设置了 `shellPath`，还要单独检查该文件是否存在、可执行且当前用户有权限访问。

> 译者注：`C:\work\repo`、`/c/work/repo` 和 `/mnt/c/work/repo` 分别可能属于 Windows、Git Bash 和 WSL 的路径表示。路径转换应由 shell 适配器或 Tool 边界负责，不能让模型猜测。

# Windows Setup

Pi uses Git Bash by default on Windows. Checked locations (in order):

1. Custom path from `~/.pi/agent/settings.json`
2. Git Bash (`C:\Program Files\Git\bin\bash.exe`)
3. `bash.exe` on PATH (Cygwin, MSYS2, WSL)

For most users, [Git for Windows](https://git-scm.com/download/win) is sufficient.

## PowerShell Tool

The optional `powershell` tool runs commands through `pwsh.exe` when available, otherwise Windows PowerShell. It starts PowerShell with `-NoProfile -NonInteractive -ExecutionPolicy Bypass`. Administrator-enforced execution policies can still take precedence.

Use `defaultTools` to replace the model-facing `bash` tool:

```json
{
  "defaultTools": ["read", "powershell", "edit", "write"]
}
```

Or enable both while comparing behavior:

```json
{
  "defaultTools": ["read", "bash", "powershell", "edit", "write"]
}
```

The `!` and `!!` editor commands still use Bash.

## Custom Bash Path

{
  "shellPath": "C:\\cygwin64\\bin\\bash.exe"
}
