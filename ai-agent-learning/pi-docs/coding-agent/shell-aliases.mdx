# Shell 别名

> 本页根据 `packages/coding-agent/docs/shell-aliases.md` 重新翻译，研究基线为 commit `853a80d26c90a14c1886f0ebb8ffaae133ca2185`。命令、配置字段、路径和 shell 语法保持原样。

## 中文译文

Pi 以非交互模式运行 bash，相当于执行 `bash -c`。这种模式默认不会展开 Shell 别名，因此交互式终端里可用的快捷命令，在 Pi 的 shell 工具中可能找不到。

要启用 shell alias，可以在 `~/.pi/agent/settings.json` 中加入：

```json
{
  "shellCommandPrefix": "shopt -s expand_aliases\neval \"$(grep '^alias ' ~/.zshrc)\""
}
```

这个值会作为前缀注入每次 shell 命令。JSON 中的 `\n` 在传给 shell 时变成换行，`\"` 则只是 JSON 对双引号的转义。路径应按照你的实际 shell 配置调整，例如 `~/.zshrc` 或 `~/.bashrc`。

展开后大致相当于：

```bash
shopt -s expand_aliases
eval "$(grep '^alias ' ~/.zshrc)"
```

`shopt -s expand_aliases` 打开 Bash 的 alias 展开；随后 `grep '^alias '` 取出配置文件中以 `alias ` 开头的行，`eval` 将这些行作为 shell 代码执行。`grep` 只匹配简单的行首 alias，不会完整加载函数、条件语句或复杂 shell 初始化逻辑。

> 译者注：`eval` 会再次解析文本，因此它不是安全的配置读取器。只应对自己信任且已检查权限的配置文件使用；不要把模型输出、网络响应或可写文件的内容直接拼接进 `eval`。

Bash 别名只在 shell 解析阶段生效，不会改变 Agent Loop 或 Tool Registry 的权限。比如 `alias deploy='git push'` 仍会执行 `git push`，短名称不代表风险更低。带参数的工作流通常应使用 shell 函数或明确的 Pi Tool，而不是强行塞进简单的 alias 提取规则。

## 安全检查

启用前至少确认：

- `.zshrc` 或 `.bashrc` 由当前用户拥有，不能被不可信用户修改；
- `grep` 取出的内容只来自你审查过的 alias 行；
- alias 不会删除文件、上传数据或修改远端仓库；
- alias 不依赖只能在交互终端中获得的状态；
- shell 命令仍受 Pi 的权限、容器网络策略和超时控制。

不要使用下面这种把远程内容交给 `eval` 的形式：

```bash
# 不要把模型或远端响应拼接到 eval
value=$(curl -fsS https://example.invalid/config)
eval "$value"
```

## Go 与 Java 对照

| Pi/TypeScript | Go | Java |
| --- | --- | --- |
| `shellCommandPrefix` | `exec.CommandContext("bash", "-c", prefix+command)` | `ProcessBuilder("bash", "-c", prefix+command)` |
| `settings.json` | `encoding/json` 解码配置 struct | Jackson 解码配置 record/类 |
| 进程取消 | `context.Context` | `Future`/`CancellationToken`/中断 |
| 命令审计 | `io.Writer` 或事件 callback | Listener/Telemetry Span |

这些只是实现类比。prefix 和 command 都应视为输入边界，先验证配置，再启动进程。

## 实验与排障

1. 在临时 alias 文件中只写 `alias pi_test='printf "alias works\\n"'`，不要直接加载真实配置。
2. 不打开 `expand_aliases`，运行 `bash -c 'pi_test'`，记录命令找不到的错误。
3. 加入 `shopt -s expand_aliases` 并执行 `eval`，再用 `type pi_test` 确认定义已经进入当前 shell。
4. 执行 `pi_test`，确认输出符合预期；再把路径改成不存在的文件，区分读取配置失败和 alias 不存在。
5. 将 alias 指向一个会失败的命令，确认“alias 已展开”和“命令执行成功”是两个状态。

| 现象 | 优先检查 |
| --- | --- |
| `ll: command not found` | 是否打开 `expand_aliases`，以及是否加载了定义。 |
| `shopt: command not found` | 实际执行入口是否是 Bash。 |
| JSON 解析错误 | JSON 字符串的反斜杠和换行转义。 |
| 终端可用、Pi 不可用 | 非交互 shell、配置文件路径和 Bash 语法差异。 |
| alias 展开后行为危险 | 展开后的真实命令、权限和网络策略。 |
| `eval` 执行了异常内容 | 配置文件的来源、拥有者和权限。 |

> 译者注：排查时应先在同一个 `bash -c` 环境中复现，再逐层加入前缀、alias 定义和真实命令。这样能区分 JSON、shell 启动、alias 查找和命令本身四种故障。
