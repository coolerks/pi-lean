# 环境变量

> 本页根据 `packages/coding-agent/docs/environment-variables.md` 重新翻译，研究基线为 commit `853a80d26c90a14c1886f0ebb8ffaae133ca2185`。环境变量名、命令、配置字段和路径保持原样。

## 中文译文

Pi 使用环境变量完成三类工作：配置 Pi 进程本身；让子进程识别 Pi 是启动者；向模型可以调用的 Shell 工具提供当前会话信息。提供方的 API key 变量另见[提供方配置](/pi-docs/coding-agent/providers#environment-variables-or-auth-file)。

## 进程标记

CLI 和 RPC 入口会设置两个进程标记：

- `AI_AGENT=pi` 是通用标记，用于让工具识别启动子进程的 Agent；
- `PI_CODING_AGENT=true` 是 Pi 专用标记，用于让子进程知道自己运行在 Pi 内部。

子进程会继承这两个标记。它们与具体会话无关，Pi 通过 SDK 嵌入其他程序时也不会自动设置它们。因此，标记只能说明启动来源，不能作为项目可信、当前用户或权限的证明。

## Shell 工具的会话环境

`bash` 和 `powershell` 工具启动命令时会收到当前 Pi 会话状态：

| 变量 | 含义 |
| --- | --- |
| `PI_SESSION_ID` | 当前会话 ID。 |
| `PI_SESSION_FILE` | 当前会话 JSONL 文件的绝对路径；临时会话中未设置。 |
| `PI_PROVIDER` | 当前选择的模型提供方。 |
| `PI_MODEL` | 当前选择的模型 ID。 |
| `PI_REASONING_LEVEL` | 当前生效的推理级别：`off`、`minimal`、`low`、`medium`、`high`、`xhigh` 或 `max`。 |

这些值在每条命令启动时解析。因此切换模型或推理级别后，下一条 Shell 命令就可能得到新值，无需重启 Pi。`PI_PROVIDER` 和 `PI_MODEL` 表示 Pi 选择的模型，不一定等于路由器最终选择的上游模型。

需要查看当前模型或提供方时，可以读取这些变量，而不是从系统提示词猜测：

```bash
printf '%s/%s\n' "$PI_PROVIDER" "$PI_MODEL"
printf 'reasoning=%s session=%s\n' "$PI_REASONING_LEVEL" "$PI_SESSION_ID"
```

持久会话的文件也可以直接查看：

```bash
if [ -n "$PI_SESSION_FILE" ]; then
  tail -n 1 "$PI_SESSION_FILE"
fi
```

这些变量只注入 LLM 可以调用的 `bash` 和 `powershell` 工具，不会注入用户输入的 `!` 或 `!!` 命令。

### 自定义 Shell 工具

通过 `createBashTool()` 或 `createPowerShellTool()` 创建并注册的工具，默认会暴露会话环境。注入发生在 `spawnHook` 之前，因此 hook 可以追加环境变量：

```typescript
const bashTool = createBashTool(cwd, {
  spawnHook: (ctx) => ({
    ...ctx,
    env: { ...ctx.env, CI: "1" },
  }),
});
```

也可以单独关闭会话元数据：

```typescript
const powershellTool = createPowerShellTool(cwd, {
  exposeSessionEnvironment: false,
  spawnHook: (ctx) => ctx,
});
```

关闭后，Pi 会移除这些变量的继承值，避免嵌套 Pi 暴露父会话的过期信息。

> 译者注：`spawnHook` 可以类比 Java `ProcessBuilder` 启动前对环境的最后一次修改，也类似 Go 对 `exec.Cmd.Env` 的设置。它能减少暴露面，但不能把已经写入日志的密钥重新变安全。

## Pi 进程配置

以下变量由 Pi 自己读取：

| 变量 | 含义 |
| --- | --- |
| `PI_CODING_AGENT_DIR` | 覆盖配置目录，默认是 `~/.pi/agent`。 |
| `PI_CODING_AGENT_SESSION_DIR` | 覆盖会话存储目录；`--session-dir` 会覆盖它。 |
| `PI_PACKAGE_DIR` | 覆盖软件包目录，适合 Nix/Guix store 路径。 |
| `PI_OFFLINE` | 关闭启动时的网络操作，包括更新检查、软件包更新和安装/更新遥测。 |
| `PI_SKIP_VERSION_CHECK` | 关闭对 `pi.dev` 最新版本的请求。 |
| `PI_TELEMETRY` | 覆盖安装/更新遥测与提供方归因请求头；可使用 `1`/`true`/`yes` 或 `0`/`false`/`no`。 |
| `PI_CACHE_RETENTION` | 设置为 `long` 时，在支持的提供方上延长提示缓存。 |
| `PI_SHARE_VIEWER_URL` | 覆盖 `/share` 使用的基础 URL。 |
| `PI_HARDWARE_CURSOR` | 设置为 `1` 时显示硬件光标；参见 [Terminal setup](/pi-docs/coding-agent/terminal-setup)。 |
| `PI_HYPERLINKS` | 用 `1`、`0` 或 `auto` 覆盖 OSC 8 超链接检测。 |
| `PI_IMAGE_PROTOCOL` | 用 `kitty`、`iterm2`、`none` 或 `auto` 覆盖行内图片检测。 |
| `PI_TRUE_COLOR` | 用 `1`、`0` 或 `auto` 覆盖真彩色检测。 |
| `PI_TUI_ESC_TIMEOUT` | 等待单独 ESC 的时间（毫秒）；SSH 默认 `100`，其他情况默认 `10`。如果 Alt 键被误识别为 Escape，可以增大它。 |
| `VISUAL`、`EDITOR` | `externalEditor` 未设置时使用的外部编辑器回退值。 |
| `HTTP_PROXY`、`HTTPS_PROXY` | 出站 HTTP 请求使用的代理。 |

提供方凭据（例如 `ANTHROPIC_API_KEY`、`OPENAI_API_KEY` 和云提供方配置）见[提供方配置](/pi-docs/coding-agent/providers#environment-variables-or-auth-file)。

## 安全边界

不要把完整的 `printenv`、API key、OAuth 刷新令牌、代理凭据、会话 JSONL 或 `/debug` 日志直接交给模型或写入 issue。给子进程提供环境变量时应使用最小允许列表；嵌套 Pi 则应关闭 `exposeSessionEnvironment`，或明确创建新的会话身份。环境变量描述的是配置或上下文，不是权限授予。

# Environment Variables

Pi uses environment variables in three ways:

- Variables such as `PI_OFFLINE` configure the Pi process.
- Pi sets process markers so child processes can identify Pi as the launching agent.
- Commands run by the LLM-callable shell tools receive `PI_*` variables describing the current session.

Provider API-key variables are documented separately in [Providers](providers.md#environment-variables-or-auth-file).

## Process Marker

The CLI and RPC entry points set two process markers:

- `AI_AGENT=pi` is a generic marker that lets tooling identify Pi as the agent that launched the process.
- `PI_CODING_AGENT=true` is Pi-specific and lets child processes detect that they run inside Pi.

Child processes inherit both markers. They are not session-specific and are not set automatically when Pi is embedded through the SDK.

## Shell Tool Session Environment

Commands run by the `bash` and `powershell` tools receive the current Pi session state:

| Variable | Description |
|----------|-------------|
| `PI_SESSION_ID` | Current session ID |
| `PI_SESSION_FILE` | Absolute path to the current session JSONL file; unset for ephemeral sessions |
| `PI_PROVIDER` | Currently selected model provider |
| `PI_MODEL` | Currently selected model ID |
| `PI_REASONING_LEVEL` | Current effective reasoning level: `off`, `minimal`, `low`, `medium`, `high`, `xhigh`, or `max` |

The values are resolved when each command starts. Switching models or changing the reasoning level therefore affects the next shell command without restarting Pi. `PI_PROVIDER` and `PI_MODEL` identify the selected Pi model, not a different upstream model that a router may choose internally.

When asked which model or provider is running, inspect these variables instead of inferring the answer from the system prompt:

```bash
printf '%s/%s\n' "$PI_PROVIDER" "$PI_MODEL"
printf 'reasoning=%s session=%s\n' "$PI_REASONING_LEVEL" "$PI_SESSION_ID"
```

The session file can be inspected directly when the session is persistent:

```bash
if [ -n "$PI_SESSION_FILE" ]; then
  tail -n 1 "$PI_SESSION_FILE"
fi
```

These variables are injected into the LLM-callable `bash` and `powershell` tools. They are not injected into user-entered `!` or `!!` commands.

### Custom Shell Tools

Tools created with `createBashTool()` or `createPowerShellTool()` expose the session environment by default when registered with Pi. Injection happens before `spawnHook`, so a hook receives the variables in `ctx.env`:

```typescript
const bashTool = createBashTool(cwd, {
  spawnHook: (ctx) => ({
    ...ctx,
    env: { ...ctx.env, CI: "1" },
  }),
});
```

Disable session metadata independently of the spawn hook:

```typescript
const powershellTool = createPowerShellTool(cwd, {
  exposeSessionEnvironment: false,
  spawnHook: (ctx) => ctx,
});
```

When disabled, Pi removes inherited values for these variables so nested Pi processes do not expose stale parent-session metadata.

## Pi Process Configuration

These variables are read by Pi itself:

| Variable | Description |
|----------|-------------|
| `PI_CODING_AGENT_DIR` | Override the config directory; default is `~/.pi/agent` |
| `PI_CODING_AGENT_SESSION_DIR` | Override session storage; overridden by `--session-dir` |
| `PI_PACKAGE_DIR` | Override the package directory, useful for Nix/Guix store paths |
| `PI_OFFLINE` | Disable startup network operations, including update checks, package updates, and install/update telemetry |
| `PI_SKIP_VERSION_CHECK` | Disable the `pi.dev` latest-version request |
| `PI_TELEMETRY` | Override install/update telemetry and provider attribution headers: `1`/`true`/`yes` or `0`/`false`/`no` |
| `PI_CACHE_RETENTION` | Set to `long` for extended provider prompt caching where supported |
| `PI_SHARE_VIEWER_URL` | Override the base URL used by `/share` |
| `PI_HARDWARE_CURSOR` | Set to `1` to show the hardware cursor; see [Terminal setup](terminal-setup.md) |
| `PI_HYPERLINKS` | Override OSC 8 hyperlink detection with `1`, `0`, or `auto` |
| `PI_IMAGE_PROTOCOL` | Override inline image detection with `kitty`, `iterm2`, `none`, or `auto` |
| `PI_TRUE_COLOR` | Override truecolor detection with `1`, `0`, or `auto` |
| `PI_TUI_ESC_TIMEOUT` | How long to wait after a lone ESC before treating it as Escape, in milliseconds; defaults to `100` over SSH and `10` otherwise. Increase if Alt-key input is misread as Escape |
| `VISUAL`, `EDITOR` | External editor fallback when `externalEditor` is unset |
| `HTTP_PROXY`, `HTTPS_PROXY` | Proxy outbound HTTP requests |

Provider credentials such as `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, and cloud-provider configuration are listed in [Providers](providers.md#environment-variables-or-auth-file).
