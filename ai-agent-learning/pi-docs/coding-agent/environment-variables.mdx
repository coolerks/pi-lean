## 中文译文

### 三种环境变量

Pi 使用环境变量完成三个不同任务，不能混为一个“配置表”：

1. `PI_OFFLINE` 等变量配置 Pi 进程本身；
2. `AI_AGENT`、`PI_CODING_AGENT` 标记子进程是由 Pi 启动；
3. `bash` 和 `powershell` Tool 收到 `PI_*` session metadata。

Provider credentials（例如 `ANTHROPIC_API_KEY`、`OPENAI_API_KEY`）另见 Providers。环境变量是输入边界，不代表它们都应被暴露给模型。尤其要区分：Pi 进程可以读取一个 key，不等于 shell tool、Skill、Extension 或 telemetry 都应该看到它。

### Process Marker

CLI 和 RPC entry point 设置：

| 变量 | 作用 | 限制 |
| --- | --- | --- |
| `AI_AGENT=pi` | 通用标记，表示启动者是 Pi | 不是 session id |
| `PI_CODING_AGENT=true` | Pi 专用标记 | 不是权限证明 |

子进程继承这两个 marker。它们不是 session-specific，所以脚本不能靠它们判断当前 lane、model 或用户。SDK embed 场景不会自动设置它们；嵌入方若设置，应明确说明是宿主自己的约定。

失败例子：脚本看到 `PI_CODING_AGENT=true`，于是把当前目录当成可信项目并执行任意 migration。这是不正确的；marker 只能说明启动来源，project trust 和 command permission 需要单独检查。

### Shell Tool Session Environment

`bash`/`powershell` Tool 启动每条命令时读取当前 session 状态：

| 变量 | 含义 | 生命周期 |
| --- | --- | --- |
| `PI_SESSION_ID` | 当前 session id | 当前 session |
| `PI_SESSION_FILE` | 当前 session JSONL 绝对路径 | ephemeral session 未设置 |
| `PI_PROVIDER` | 当前选择的 Provider | 下一条 command 开始时解析 |
| `PI_MODEL` | 当前选择的 model id | 不是 router 最终上游 model |
| `PI_REASONING_LEVEL` | effective reasoning level | `off`/`minimal`/`low`/`medium`/`high`/`xhigh`/`max` |

切换 model 或 reasoning level 后，不需要重启 Pi；下一条 shell command 会获得新值。Router 内部选择的 concrete model 可能不同，不能从 `PI_MODEL` 推断最终计费对象。

查看示例：

```bash
printf '%s/%s\n' "$PI_PROVIDER" "$PI_MODEL"
printf 'reasoning=%s session=%s\n' "$PI_REASONING_LEVEL" "$PI_SESSION_ID"
if [ -n "$PI_SESSION_FILE" ]; then
  tail -n 1 "$PI_SESSION_FILE"
fi
```

这些变量只注入 LLM-callable `bash`/`powershell`，不会注入用户输入的 `!` 或 `!!` command。原因是后两者是用户直接执行的 shell 表面，不应被误认为模型工具上下文。`PI_SESSION_FILE` 的最后一行也可能是敏感内容，调试时只在临时 workspace 使用。

### Custom Shell Tools 与 spawnHook

> 译者注：`spawnHook` 类似 Java 的 `ProcessBuilder` 包装器或 Go 对 `exec.Cmd.Env` 的最后一次改写。它能改变子进程环境，但不能把已经泄漏的 secret 重新变安全；调试时只打印变量名。

`createBashTool()` 和 `createPowerShellTool()` 默认暴露 session environment。注入发生在 `spawnHook` 之前，因此 hook 可以在继承基础上追加 `CI=1`：

```typescript
const bashTool = createBashTool(cwd, {
  spawnHook: (ctx) => ({
    ...ctx,
    env: { ...ctx.env, CI: "1" },
  }),
});
```

要独立关闭 session metadata：

```typescript
const powershellTool = createPowerShellTool(cwd, {
  exposeSessionEnvironment: false,
  spawnHook: (ctx) => ctx,
});
```

关闭后 Pi 会移除这些变量的 inherited values，避免嵌套 Pi 把父 session 的旧 id、旧 model 或旧文件路径暴露给子进程。`spawnHook` 的输入是准备 spawn 的上下文；不要在 hook 中打印整个 `ctx.env`，因为其中可能已有凭据。

### Pi Process Configuration

下面这些变量由 Pi 自己读取：

| 变量 | 含义与注意 |
| --- | --- |
| `PI_CODING_AGENT_DIR` | 覆盖 `~/.pi/agent` config directory |
| `PI_CODING_AGENT_SESSION_DIR` | 覆盖 session storage；`--session-dir` 优先 |
| `PI_PACKAGE_DIR` | 覆盖 package directory，适合 Nix/Guix path |
| `PI_OFFLINE` | 关闭 update check、package update、install/update telemetry 等启动网络操作 |
| `PI_SKIP_VERSION_CHECK` | 关闭 `pi.dev` latest-version request |
| `PI_TELEMETRY` | `1/true/yes` 或 `0/false/no`，覆盖 install/update telemetry 与 attribution header |
| `PI_CACHE_RETENTION` | `long` 时在支持的 Provider 延长 prompt cache |
| `PI_SHARE_VIEWER_URL` | 覆盖 `/share` 使用的 viewer base URL |
| `PI_HARDWARE_CURSOR` | `1` 时显示硬件 cursor，关联 Terminal setup |
| `PI_HYPERLINKS` | `1`、`0` 或 `auto` 覆盖 OSC 8 detection |
| `PI_IMAGE_PROTOCOL` | `kitty`、`iterm2`、`none` 或 `auto` |
| `PI_TRUE_COLOR` | `1`、`0` 或 `auto` |
| `PI_TUI_ESC_TIMEOUT` | lone ESC 等待毫秒数；SSH 默认 100，其他默认 10 |
| `VISUAL`/`EDITOR` | `externalEditor` 未设置时的 editor fallback |
| `HTTP_PROXY`/`HTTPS_PROXY` | outbound HTTP proxy |

`PI_CODING_AGENT_SESSION_DIR` 与 CLI `--session-dir` 存在优先级时，以命令行参数为准。`PI_OFFLINE` 不是“禁止所有网络”：它控制 Pi 启动阶段列出的网络操作，Provider request 是否可用仍取决于运行模式和调用方式。代理变量还可能改变 Provider 和 package 的出站路径。

> 译者注：环境变量的“优先级”必须按具体字段验证。命令行优先于 session directory 的事实来自源文档；不能把它推广成所有 settings、Provider auth 和 Extension config 都遵循同一层级。遇到冲突应打印最终 effective config，而不是只打印输入来源。

### 优先级、嵌套进程与安全

建议按这个顺序排查配置：命令行显式选项 -> Pi config/settings -> 进程环境变量 -> 默认值；具体字段以当前实现为准，不要把这个通用顺序当成每个变量的 API 保证。Session metadata 在每条 Tool spawn 时解析，Provider auth 则按 Providers 的 credential resolution 规则解析。

不要把 `printenv` 的完整结果交给模型或写进 issue。API key、OAuth refresh token、proxy credentials、session JSONL 和 `/debug` log 都应当脱敏。使用最小环境 allowlist 给子进程，而不是把宿主全部环境传给 shell。嵌套 Pi 要么关闭 `exposeSessionEnvironment`，要么明确生成新的 session identity。

### Go 与 Java 对照

| Pi | Go | Java |
| --- | --- | --- |
| `process.env` | `os.Getenv` | `System.getenv` |
| child env | `exec.Cmd.Env` | `ProcessBuilder.environment()` |
| command cancellation | `context.Context` | `Future`/interrupt |
| config dir | `os.UserHomeDir` + Path | `System.getProperty("user.home")` + Path |

这只是 API 对照，不表示 Go/Java 会自动得到 Pi 的 session metadata。自己的 Harness 应显式决定哪些字段进入 Tool context，并把 key 与 metadata 分开。

> 译者注：最危险的错误是把 `System.getenv()` 或 `os.Environ()` 全量交给模型可调用的 shell。正确做法是先建立 allowlist，再把不敏感的 session metadata 单独注入；认证凭据应由 Provider adapter 或受控代理消费。

### 实验与小结

1. 用一个 fake shell tool 打印变量名而不是值，确认 session metadata 注入位置。
2. 切换 model/reasoning level，再运行下一条 command，观察值变化。
3. 设置 `PI_CODING_AGENT_SESSION_DIR`，再用 `--session-dir`，确认实际优先级。
4. 设置 `exposeSessionEnvironment:false`，启动嵌套 Pi，确认旧值不会泄漏。
5. 让日志故意包含一个 dummy key，练习 redaction；不要使用真实凭据。

环境变量既是配置，也是进程边界。marker 只说明来源，session `PI_*` 只说明当前上下文，Provider key 只用于认证；三者的生命周期、可见范围和安全等级都不同。

# Environment Variables

Pi uses environment variables in three ways:

- Variables such as `PI_OFFLINE` configure the Pi process.
- Pi sets process markers so child processes can identify Pi as the launching agent.
- Commands run by the LLM-callable shell tools receive `PI_*` variables describing the current session.

Provider API-key variables are documented separately in [Providers](providers.md#environment-variables-or-auth-file).

## Process Marker

The CLI and RPC entry points set two process markers:

- `AI_AGENT=pi` is a generic marker that lets tooling identify Pi as the agent that launched the process.
- `PI_CODING_AGENT=true` is Pi-specific and lets child processes detect that they run inside Pi.

Child processes inherit both markers. They are not session-specific and are not set automatically when Pi is embedded through the SDK.

## Shell Tool Session Environment

Commands run by the `bash` and `powershell` tools receive the current Pi session state:

| Variable | Description |
|----------|-------------|
| `PI_SESSION_ID` | Current session ID |
| `PI_SESSION_FILE` | Absolute path to the current session JSONL file; unset for ephemeral sessions |
| `PI_PROVIDER` | Currently selected model provider |
| `PI_MODEL` | Currently selected model ID |
| `PI_REASONING_LEVEL` | Current effective reasoning level: `off`, `minimal`, `low`, `medium`, `high`, `xhigh`, or `max` |

The values are resolved when each command starts. Switching models or changing the reasoning level therefore affects the next shell command without restarting Pi. `PI_PROVIDER` and `PI_MODEL` identify the selected Pi model, not a different upstream model that a router may choose internally.

When asked which model or provider is running, inspect these variables instead of inferring the answer from the system prompt:

```bash
printf '%s/%s\n' "$PI_PROVIDER" "$PI_MODEL"
printf 'reasoning=%s session=%s\n' "$PI_REASONING_LEVEL" "$PI_SESSION_ID"
```

The session file can be inspected directly when the session is persistent:

```bash
if [ -n "$PI_SESSION_FILE" ]; then
  tail -n 1 "$PI_SESSION_FILE"
fi
```

These variables are injected into the LLM-callable `bash` and `powershell` tools. They are not injected into user-entered `!` or `!!` commands.

### Custom Shell Tools

Tools created with `createBashTool()` or `createPowerShellTool()` expose the session environment by default when registered with Pi. Injection happens before `spawnHook`, so a hook receives the variables in `ctx.env`:

```typescript
const bashTool = createBashTool(cwd, {
  spawnHook: (ctx) => ({
    ...ctx,
    env: { ...ctx.env, CI: "1" },
  }),
});
```

Disable session metadata independently of the spawn hook:

```typescript
const powershellTool = createPowerShellTool(cwd, {
  exposeSessionEnvironment: false,
  spawnHook: (ctx) => ctx,
});
```

When disabled, Pi removes inherited values for these variables so nested Pi processes do not expose stale parent-session metadata.

## Pi Process Configuration

These variables are read by Pi itself:

| Variable | Description |
|----------|-------------|
| `PI_CODING_AGENT_DIR` | Override the config directory; default is `~/.pi/agent` |
| `PI_CODING_AGENT_SESSION_DIR` | Override session storage; overridden by `--session-dir` |
| `PI_PACKAGE_DIR` | Override the package directory, useful for Nix/Guix store paths |
| `PI_OFFLINE` | Disable startup network operations, including update checks, package updates, and install/update telemetry |
| `PI_SKIP_VERSION_CHECK` | Disable the `pi.dev` latest-version request |
| `PI_TELEMETRY` | Override install/update telemetry and provider attribution headers: `1`/`true`/`yes` or `0`/`false`/`no` |
| `PI_CACHE_RETENTION` | Set to `long` for extended provider prompt caching where supported |
| `PI_SHARE_VIEWER_URL` | Override the base URL used by `/share` |
| `PI_HARDWARE_CURSOR` | Set to `1` to show the hardware cursor; see [Terminal setup](terminal-setup.md) |
| `PI_HYPERLINKS` | Override OSC 8 hyperlink detection with `1`, `0`, or `auto` |
| `PI_IMAGE_PROTOCOL` | Override inline image detection with `kitty`, `iterm2`, `none`, or `auto` |
| `PI_TRUE_COLOR` | Override truecolor detection with `1`, `0`, or `auto` |
| `PI_TUI_ESC_TIMEOUT` | How long to wait after a lone ESC before treating it as Escape, in milliseconds; defaults to `100` over SSH and `10` otherwise. Increase if Alt-key input is misread as Escape |
| `VISUAL`, `EDITOR` | External editor fallback when `externalEditor` is unset |
| `HTTP_PROXY`, `HTTPS_PROXY` | Proxy outbound HTTP requests |

Provider credentials such as `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, and cloud-provider configuration are listed in [Providers](providers.md#environment-variables-or-auth-file).
