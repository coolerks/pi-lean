# Tool 与安全边界

`read("~/.ssh/id_rsa")`、`bash("rm -rf ...")`、`curl` 和 `git push` 都说明同一个问题：模型输出不是授权。即使 JSON Schema 合法，也可能违反项目策略。

## 建议的执行管线

```text
model tool call
 -> parse
 -> schema validation
 -> normalize path/command
 -> permission policy
 -> user approval（必要时）
 -> sandbox / timeout / resource limit
 -> execute
 -> redact secrets
 -> tool result
```

Pi 当前有项目可信度、工具配置、shell 执行和 sandbox 相关设计，但不能把它描述成“所有命令自动安全”。具体看 `packages/coding-agent/docs/security.md`、`src/core/project-trust.ts`、`src/core/trust-manager.ts` 和 bash executor。

## 教学实现的限制

Go/Java 示例的 `PermissionPolicy` 只限制工作目录和明显的危险命令；它不是操作系统沙箱。生产环境需要容器、最小权限账户、网络策略、超时、CPU/内存限制、secret redaction 和审计日志。

<Warning>

不要用真实 home 目录、SSH 凭据或生产仓库运行示例中的 shell Tool。测试使用临时目录和 `ScriptedModel`。

</Warning>
