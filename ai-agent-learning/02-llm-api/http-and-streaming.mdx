# HTTP、SSE 与 Streaming

## 先做普通请求

最小路径只有四步：组装 JSON、加入 `Authorization`、发送 HTTP POST、检查状态码并解码 JSON。生产代码必须区分 401/403（认证）、429（限流）、5xx（服务端）和 invalid JSON；不要把所有错误都当成模型拒绝。

## SSE 是什么

Server-Sent Events 是服务器通过一个长 HTTP 响应向客户端发送事件。每条事件通常由若干 `data:` 行和空行组成；`data: [DONE]` 不是所有 Provider 都使用。解析器应按事件边界处理，而不是对每个网络 chunk 假设一条完整 JSON。

```text
HTTP response body
data: {"delta":"Hel"}\n\n
data: {"delta":"lo"}\n\n
```

网络 chunk 可能把 `{"del` 和 `ta"...}` 分开，也可能一个 chunk 包含多条事件。Go 版用 `bufio.Scanner`/自定义行缓存，Java 版用 `HttpResponse.BodyHandlers.ofLines()` 或字节缓冲；二者都要测试分片边界。

## Pi 的流契约

`packages/ai/src/utils/event-stream.ts` 的 `EventStream<T, R>` 同时实现 `AsyncIterable<T>` 和最终 `result()` Promise。`AssistantMessageEventStream` 要先发 `start`，再发 `text_delta`、`thinking_delta`、`toolcall_delta` 等事件，最后以 `done` 或 `error` 收束。这个设计把“实时 UI”与“最终消息”连接起来。

`packages/agent/src/agent-loop.ts` 用 `for await (const event of response)` 消费它。注意 TypeScript 的 `AsyncIterable` 类似 Java 的异步事件回调组合，但不是 Java `Iterator` 的同步版本。

## 练习

1. 用 Fake HTTP server 返回被任意切分的 SSE。
2. 验证最终 `AssistantMessage` 与逐个 delta 拼出的内容一致。
3. 在中途触发 `AbortSignal`，确认结果是 `stopReason: "aborted"`，而不是一个永远等待的 Promise。
